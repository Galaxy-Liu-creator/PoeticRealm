## 核对结论与设计契约

设计归档结构可沿用，但旧路线图、验收与架构遗漏账号三页，阶段停在 S01 v02 待审，与实际 v09 选图不一致。推荐图采用 design/README 的混合版本清单，保留历史与来源。

视觉：青黛山水题头、浅绢纸、三张等高诗卡和收藏书签。题头、收藏页右侧山景与个人中心左右栏是主要记忆点。青黛用于文字与操作，朱砂仅用于已收藏，细金线用于原稿已有的边饰；圆角约 8–12px，按钮书卷式细边。中文标题采用本机楷体候选，正文宋体与可读界面字体；不分发系统字体，正式行书字体待合法素材补齐。

主页三卡桌面并列，收藏卡保持主页尺寸，个人中心左栏约 27%、右栏约 73%。桌面 1440/1536 与 1920 验证，较小窗口允许换列，不新增移动版设计。DOM 保留原诗阅读顺序，竖列右起，焦点可见，表单有 label，状态由文字说明。纸面、书签、按钮圆角均是用户原图选择；不新增光晕、营销徽章、假数据或额外持续特效。

## 实施阶段

1. 保留 P0 入口：将实验代码独立，显式 scene/debug/t/q 参数继续访问；默认入口改为总览。
2. 新增 hash 路由、诗词数据、公共导航/诗卡；还原总览、收藏、个人中心和三诗静态预览 UI。
3. 本机收藏、资料、头像、浏览记录与偏好，版本化存储；失败明确提示并保留会话数据，用户输入转义。头像本地解码、裁切为 256px，不上传。
4. 账号三页与双幅拉幕。未提供认证服务时，表单验证后说明未接入，不保存密码、不伪造登录成功；通知/推荐无服务时禁用并解释。
5. 类型检查、现有单元测试、构建；新增数据与路由边界测试。Playwright 检查 9 页、收藏同步/刷新/空态、资料、无效路由、历史、键盘、缩窗、reduced-motion、控制台与图片资源。截图放本目录 assets，报告记录真实边界。

R1 不重写 Three.js、GLB 或 CONTRACT，不承诺火/雪/云水/翻页的屏幕合成或实时场景达标。三诗可进入明确标注的静态预览；素材许可未核实前不部署。
