# 03 · 分段制作与材质交接

[返回建模目录](README.md) · 上一篇：[组件与装配](02-组件与装配.md) · 下一篇：[自然动态与演出](04-自然动态与演出.md)

采用当前Blender5.1.1，通过MCP执行可复现Python建模、查看与局部修订；同类重复构件可使用修改器或Geometry Nodes。具体API和导出参数以当前工具版本及CONTRACT为准。

## 每段制作循环

1. 列明组件的输入、尺寸参数、输出集合、连接位置和依赖，确认本次修改范围。
2. 制作基本轮廓、实体厚度和结构，检查法线、比例、接合及必要封闭性。
3. 精修近景可见构造；通过视口与实际镜头检查后保存组件检查点。
4. 制作高模细节、实时低模与UV，烘焙并配置材质。
5. 将已检查组件组装到主体，检查承托、间隙、遮挡及水位关系。
6. 阶段产物经校验和统一导出后，在真实浏览器检查；修正受影响组件及依赖，再复验。

每次调用只覆盖一个组件或职责明确的小组件组；同类瓦片、椽子、叶片可批量生成。装配不能隐藏整场从零生成。修改前确认场景、集合和保存状态，保留历史修订及无关对象。

## 复杂细节的三层分工

| 层 | 保留内容 | 处理方式 |
|---|---|---|
| 可见结构 | 檐口、屋角、梁柱接合、桥拱、舟壳、主树枝、大岩缝 | 保留真实轮廓、厚度和承托几何 |
| 高模表面 | 倒角、细小缺口、木材纹理、石面凹凸、瓦面磨损 | 作为烘焙来源，工作集合不直接发布 |
| 实时网格 | 必要轮廓与接合，距离层级、UV和法线 | 降低细分，静态按空间块/材质优化，重复构件共享几何 |

动态舟、人物骨骼、桨、植被、相机和挂点排除不适当静态合并。制作源继续保留组件边界。Geometry Nodes和修改器须落实为契约支持的网格或实例结构；不假定未应用的节点系统能直接导出。

## 材质输入

| 材料 | 制作要点 |
|---|---|
| 木构 | 木纹沿构件长轴，梁柱与舟板共享合理尺度；磨损保留暗部层次 |
| 石材 | 接缝与凹凸尺度匹配米制；近水干湿过渡结合颜色、粗糙度和反射校准 |
| 屋瓦 | 屋面方向、瓦缝和檐口接合正确，檐下AO与实时阴影配合 |
| 枝叶、芦苇 | 共享原型与贴图，叶背、裁切、alphaTest及风摆阴影一起检查 |
| 钟与小金属件 | 几何轮廓保留，细纹和磨损进入法线/粗糙度；按材质性质配置金属度 |

按v0.2提供Base Color、Normal和Roughness，需要时补AO；ORM约定R=AO、G=Roughness、B=Metallic。色彩图与法线/ORM等数据图按契约处理颜色空间。优先共享1K纹理，近景确有需要才使用2K；法线和粗糙度不无条件有损转码。

`mask` 是行为数据，不能当表面颜色；根部到叶尖的风摆权重须在优化后保持。源程序材质烘成可导出贴图；木纹方向、UV密度、法线方向及粗糙度都在浏览器复查。

## 导出与代码接口

CONTRACT → 制作/Node校验 → 导出、资产与加载同步更新。新增完整场景清单及节点按同一流程落地，本目录不新增未登记的属性或接口。

源文件保留在art，统一导出到frontend/public/assets。发布来源登记CREDITS；工作高模、参考、辅助灯与水不混入导出集合。压缩前后对照节点、父子关系、骨骼、相机、材质、UV、遮罩和图像，随后检查真实固定帧。
