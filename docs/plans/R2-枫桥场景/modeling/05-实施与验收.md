# 05 · 制作批次与验收

[返回建模目录](README.md) · 上一篇：[自然动态与演出](04-自然动态与演出.md)

## 制作顺序与进入条件

| 批次 | 分段制作内容 | 可审阅产物 | 进入下一批的条件 |
|---|---|---|---|
| A · 构图与压缩 | 布局、水位、五机位；当前舟与人物资产优化 | 布局视角、压缩候选、全场预算表 | 绑定/材质/节点未损坏，确实腾出预算；舟壳封闭及97姿态门禁仍通过 |
| B · 桥寺主体 | 台基柱网 → 梁架椽檐 → 屋面围护；钟架钟体；桥台拱圈 → 桥面栏杆 | 主殿、钟楼/钟、石桥组件及组合GLB | 承托、唐风轮廓、厚度与阴影清楚；纹理尺度合理，构图不挡舟和诗文 |
| C · 石岸与植被 | 岸坡水线 → 岩块碎石；树干枝条 → 叶簇；芦苇单簇 → 散布 | 原型、固定种子布局与风摆 | 无漂浮、穿水和明显重复块阵；树冠有层次，植物形变/阴影一致 |
| D · 夜景与演出 | 月落、薄雾、灯水联调；四句镜头、乌啼/钟声/水声、三维转场 | 完整枫桥实际浏览器画面、连续录像与音频 | 固定时刻、暂停/seek、声音、取消/返回及完整性能/释放通过 |

每批内部仍按组件分段，不把“一个批次”理解成一次整体生成。发现问题优先修正组件及依赖，再复验受影响内容。

## 近远层级制作

在C进入D前，另存scene-v02，保留scene-v01与舟v01–v04。远景按寺/钟楼屋面、寺/钟楼木构、基座围护与钟、桥拱栏杆、枫枝、枫叶、芦苇分别制作和检查，再复制已检查组件组装。近景保留原几何；远景保留屋脊鸱尾、宽檐、柱网、桥孔和树冠轮廓，减少瓦垄圆周、椽斗细节与叶片内部面数。UV、PBR、风权重和原点继续遵守契约。

运行端以主相机到近景组件包围盒中心的米制距离选层，每次更新只选一次，主画面、倒影与阴影共用；不让倒影相机重新选层。层级选择无历史状态，seek与手动选机位可复现。所有层级预热，关闭页时释放隐藏层资源。

建筑和岸石可在运行端按相同材质及阴影设置合并静态绘制，按需要缓存建筑近远组合，至多8组；初始化只合并起始层级，提前预编译所有材质与布局的着色器。保留资产节点和原网格供接口与对照检查。风动、人物与舟不进入静态合并。合并坐标的Float32舍入必须通过严格截图差异检查，不能宣称几何量化无损；自有合并几何单独释放，共享材质仍归资产所有。资源复查先覆盖相同机位与层级，再比较重载计数。

每帧动画结束后统一更新场景矩阵，倒影与主画面读取同一帧矩阵；船体之外的水面可提前排除不可能进入船舱的计算。此类优化保留原分辨率、效果和遮挡公式，八机位开关对照要求逐像素一致。不得按历史帧缓存动态阴影或倒影来掩盖seek问题。

复查阈值前后连续移动、八制作机位、风摆根部/阴影/倒影、近景原细节和远景轮廓。总分发预算计入所有近远模型与环境，性能继续使用完整效果三轮60秒及原50fps/P95门禁。开关效果只用于定位开销。

## 每段与每批检查

- 每段：尺寸、原点、缩放、命名、法线、厚度、接合和必要封闭性；保存源组件检查点。
- 每批：制作校验、GLB契约与预算、真实浏览器材质/阴影/反射、实际机位固定帧和连续动态。
- 桥：正面、侧面、桥下、入岸与倒影；寺钟楼：掠射光、檐下、钟悬挂关系和远景轮廓。
- 自然：近水水线、枫树疏密、叶背与裁切、根部、风摆阴影、雾与倒影一致性。
- 舟相关改动：97个实际划桨姿态与几何检查、连续录像及首尾/侧面复查；离散采样不声称连续碰撞证明。

## 完整场景门禁

1920×1080/DPR1和1440×900实际页面检查诗文、导航、键盘及遮挡。固定seed下采样t=0/8/16/24/32，并补渔火峰值、摆舟极值和钟声抵达前后。减少动态仍保留可读内容与手动选句。

性能在当前笔记本预热后测三轮各60秒，目标≥50fps、P95≤20ms，记录>50ms长帧、多pass调用和三角形。追踪与无追踪播放分开，浏览器帧间隔不冒称纯GPU耗时。实际硬预算遵守CONTRACT，答辩机R4另验。

至少十次进入/退出，资源计数回到可解释基线，检查加载中取消、快速再进、缺失/损坏资产、迟到结果、后台暂停及返回恢复。音频需实听，并验证解锁失败、静音和退出释放。

## 验证与证据归档

按改动范围执行Blender validate、统一export和已实现的Node契约/预算门禁；运行代码变更执行相关测试和构建。全场检查必须补全正式场景清单，不能以quality-sample通过替代。

Chrome DevTools MCP检查实际DOM、Console、截图与性能；Playwright检查操作、取消、固定时刻和连续流程。证据放阶段assets下独立修订目录，保留图像、原始视频、JSON、日志、来源和时间信息；不覆盖既有sample-v01–v04证据。

实际进度、通过结果、失败与限制只写根HANDOFF。枫桥完整关口通过后进入R3，R4收敛目标机、许可、离线包和演示交付。
