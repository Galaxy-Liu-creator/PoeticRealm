# R2 · 枫桥场景建模与动态实施方案

2026-10-06。依据用户本轮要求、《设计文档》第 8、13–19 章、CONTRACT 和 STORYBOARD。先证明“湿石岸＋木舟＋江面＋夜间渔火”，枫桥验收后再进入江雪、白帝城和最终交付。性能先用当前开发笔记本，答辩机确定后复验；当前任务状态与实际验证只写根 HANDOFF.md。

## 1. 制作目标与边界

视觉方向沿用“青黛山水 · 写实诗境”：蓝灰冷江、湿石与有构造的木舟，局部暖渔火，近岸／桥舟／寺与远山形成空间层次。薄雾提供寒意和留白，诗文仍为右起竖排 DOM，保留左上安全区。建筑做有依据的唐风艺术场景，不声称精确复原唐代寒山寺。

保留原生 TypeScript、Three.js **0.186.1**、WebGLRenderer、GLSL、GSAP 3.15.0 与现有认证/hash 路由。Blender 制作复杂主体；自然系统放 frontend/src/systems 和 shaders；scenes 只负责配置、装配和分镜。P0 实验和既有生成/验证历史保留。

首版规划时接口为 v0.1；下文第 2、5 节保留当时的基线和迁移设计。现行契约及实际验证以 CONTRACT、HANDOFF 为准，2026-10-07 的后续制作顺序见第 12 节；接口变更仍须先登记契约，再同步校验、导出、资产和加载代码。

## 4. 复杂主体如何建模

### 4.1 制作方式

以 Blender Python 参数化结构、修改器/Geometry Nodes 重复构件、人工检查镜头和轮廓相结合。脚本负责有尺寸关系的结构与批量重复；最终可见结构、比例和轮廓仍须按参考与浏览器结果精修。

1. 在 Blender 确定米制场景、河岸/水位、桥寺舟的位置及五个镜头；把诗文安全区作为构图约束。
2. 制作需要真实几何的轮廓和接合；高模增加磨损、凹缝和纹理细节。
3. 生成实时低模，展开 UV、统一材质尺度；高模细节烘焙到切线法线、AO/粗糙度等贴图。
4. 导出实时版本，浏览器检查轮廓、法线、材质方向、阴影和实际镜头距离，再回 Blender 修正。

远、中、近景按最大屏幕占比配置精度；LOD 阈值依实测确定，近景轮廓不靠法线贴图替代。运行端不临时拼盒体充当寺桥舟成品。

### 4.2 各主体的几何与材质分工

| 主体 | Blender 中真实制作 | 贴图/运行时承担 |

| 木舟 | 用横截面曲线/放样生成船壳，做船板厚度、舷缘、肋骨、横梁、篷架和系泊结构；摆动根节点设在合理浮动中心 | 船板 UV 顺木纹；磨损/水线/木纹烘焙；船体变换与水面同源波函数；灯火/声源作为子挂点随舟移动 |
| 枫桥 | 拱券截面、桥面坡度、桥台与栏杆；有限种类石块按结构排列，避免重复感 | 石缝/磨损烘焙；近水湿度；桥下阴影、桥拱倒影在实际镜头中验收 |

寺桥的建筑类型和比例须先核查参考；不直接套用现代寒山寺照片中的形制。允许脚本制作基础，也允许引入有明确可修改/分发许可的模型作为起点，必须记录来源并适配契约；不依赖未授权付费或 AI 三维生成服务。概念图只指导构图/色调，不作为可导出的主体资产。

## 5. CONTRACT v0.2 的迁移设计

### 5.1 保持与新增

保留米制、坐标换算、标记命名、既有 PLACE_、mask 语义、RG 高度与 B 引导编码。旧 ink_* 资产和 P0 入口保留兼容；新增写实资产采用显式材质配置，避免旧灰模被悄然重新解释。

拟新增 pbr_rock / pbr_stone / pbr_wood / pbr_tile / pbr_foliage / pbr_cloth / pbr_metal 槽位，继续最多两槽/物体；water/glow 继续作为专用效果。材质必须有已登记角色，不能只凭名字猜效果。

场景资产清单拟加入 contractVersion、材质配置、GLB/纹理/地形/音频文件列表与校验引用。字段与文件名在 v0.2 中一次定义；运行时拒绝不支持版本并显示重试/错误，不静默退成失真的场景。小样与正式枫桥区分必需节点清单，其他两首不因目录占位被误报通过。

### 5.2 PBR 输入与遮罩

写实材质采用 glTF metallic-roughness：Base Color、Normal、Roughness/Metallic、AO，以及渔火所需的 Emissive。石/木/瓦使用近零金属度；湿石效果由粗糙度、法线与光照共同产生。

- Base Color/Emissive 色彩贴图按 sRGB，法线/粗糙度/AO 等按非色彩数据处理；自定义水材质和后处理统一输出转换，避免重复调色。
- ORM 约定 R=AO、G=Roughness、B=Metallic；切线法线约定 +Y，明确 UV 通道、normalScale 与法线烘焙方向。AO 的 UV 绑定按本机 0.186.1 实现核对，不硬套旧版 UV2 规则。
- 新 PBR 带纹理的石岸也需要 UV，不沿用旧 ink_stone 无 UV 的默认。纹理尺寸沿用 ≤2K，贴图尺度由实际米制校验。
- **mask 是数据，不是表面颜色。** 现有导出把 mask 放在 COLOR_0，本机 GLTFLoader 会因此启用 vertexColors。v0.2 写实配置加载后把它明确映射为行为遮罩属性，关闭误用的表面颜色乘法；R 保持风摆，G 保留原语义，材质 AO 另走 AO 纹理。旧水墨路径维持原处理。
- 用已知 0/0.5/1 遮罩值做 Blender→GLB→浏览器往返检查，防止颜色管理、压缩或合并改变权重；真实顶点染色如后续需要，单独登记，不能与 mask 混用。

默认保留 GLTFLoader 生成的 MeshStandardMaterial/PBR 输入，只对风摆/湿度等必要部分做受版本检查的 GLSL 扩展；动态几何的深度/阴影材质必须应用相同形变。先不把所有主体替换为全手写 ShaderMaterial。

## 6. 江面、天空与自然动态

夜景先建立固定曝光下的冷色天空/环境反射与低强度月光，再加入局部暖渔火。主体优先保留一盏重点投影灯：月光方向灯覆盖近岸与舟，阴影范围按镜头收紧，比较 1024/2048 阴影贴图；其余渔火先不投影，必要时仅近景增加局部聚光阴影。点光投影的多面成本单独实测，避免每盏渔火都启用。接缝/檐下的 AO 配合实时阴影，不把大面积黑色 AO 烘进 Base Color。渔火峰值与月落末态都检查暗部可读、亮部不过曝；Bloom 只作为通过基础光照后的小幅选项。

| 系统 | 首版实现 | 必须验证的边界 |
|---|---|---|
| 江面 | GLSL 低振幅解析波形＋细节法线；基于视角的反射权重；水线/岸边衔接 | 表面不呈果冻或大海；近岸不穿石，船不漂浮在水上方 |
| 倒影 | 一个可控分辨率的平面反射 RT，包含选定舟、岸、桥寺轮廓和渔火；环境反射补充天空 | 禁止水面反射自身/递归；雾/透明层另控，色彩与主体一致；月火倒影随水法线破碎 |
| 湿石反射 | PBR＋环境反射，必要时局部环境近似 | 江面平面反射并不会自动作用于石岸；必须独立检查湿石受光，不能只调水面 |
| 天空/月落 | 分层夜空＋远处月面；按 scene time 向地平线落下，环境亮度同步缓变 | “霜满天”表现寒意；月落后不在 32 秒尾帧突然重新出现 |
| 薄雾 | 距离/高度雾＋少量局部低频雾片；颜色服从冷江/暖火 | 舟/桥寺有前后层次，不用全屏模糊；反射 pass 雾规则一致；透明排序和重叠成本可控 |
| 渔火 | 小型火形/发光层＋有限局部灯；固定种子和低频亮度/形状变化 | Emissive 不自动照亮舟岸，必须有实际灯光；不让 Bloom 盖住物体构造 |
| 船体轻摆 | 用同一水面高度函数采样浮动点，计算轻微升沉/俯仰/横摇；系泊舟漂移受约束 | 船、灯、声源和倒影一致；预留自定义 bob 与水系统耦合，不叠两套升沉 |
| 植被/落叶 | 共用风场，mask 控制分支；稀少落叶由 seed＋t 求位置 | 根部固定；风摆的阴影一致；不用每帧重新抽随机数 |
| 地形/远山 | 继续读取既有高度图，不启用纸面生长；近岸复杂轮廓用局部 GLB，远山按视距细化 | 高度场不能表达洞/悬挑，桥拱、岸壁另用几何；1.5km 场景/1024 图的精度不足以替代近岸石缝 |

反射先比较 512 档与 1024 档，以及随镜头/物体变化的更新频率；只在结果连续且性能有余量时提高。低档保留可辨认的舟/渔火倒影，先降反射分辨率、参与对象和阴影范围；不直接删掉要求的倒影。首版不以 SSR、全场体积雾或流体求解器为依赖。

固定 t/seed 下所有自然系统返回相同状态。解析波、风摆、渔火优先纯函数；若确需粒子/流体积分，采用固定步和确定性重建，不以帧率决定结果。realDt 仅推进 Clock，画面取 scene time。

## 7. 四句镜头与钟声

沿用 STORYBOARD 的 32 秒作为首版演出提案，最终节奏根据浏览器观看再定。镜头来自 Blender 的 CAM_/FOCUS_；不把坐标写进 timeline。

| 场景时间 | 镜头与画面 | 声音 |
|---|---|---|
| 0–8 s | CAM_enter 平滑接 CAM_moonset，月落、冷江、寒意 | 低强度江风、远乌啼 |
| 8–16 s | CAM_riverbank，湿岸、江枫、木舟、渔火和倒影 | 舟边水声与轻微木构声 |
| 16–24 s | CAM_temple，桥寺/钟楼从有层次的雾中显出 | 环境声克制，给钟声留空间 |
| 24–32 s | CAM_boat，钟声意象从寺前到客船，镜头稳定停留 | 抵船时播放钟声及长尾 |

先补齐缺失的 CAM_moonset、CAM_riverbank、CAM_temple、FOCUS_temple、FOCUS_boat 等契约节点。相机插值限制速度和角速度、不滚转；相机位置/FOV、焦点和诗文安全区共同验收。提供 Cinematic、受限 Orbit、点击诗句 Focus；不实现首版之外的自动导游或任意无限漫游。

钟声事件的传播起点引用 EMIT_bell，抵达目标取 boat_guest 的世界坐标，水平距离与既有契约一致：arrival = emitTime + distance / 340。当前约 956m 只用于灰模回归，不锁死新场景；新布局须重新计算并自动检查事件落在第四句窗口。

波前是艺术化声传播提示，与真实江面细波分开，不将 340m/s 当作水波速度。声音已经按抵达时间安排时不再加第二次传播延迟。空间声的位置/朝向、衰减和响度要实听；寺与船相距较远时采用明确的艺术化响度配置，不让默认衰减导致钟声不可闻。

AudioEngine 新建用户手势 unlock、环境/音效/人声/音乐分轨、音量/静音、pause/seek/exit。点击入境按钮时即请求解锁，不等异步 GLB 下载后才用失效手势；声音被拒绝不阻挡导航。场景音频以正式进入为时间零点；隐藏暂停，取消清安排，退出淡出并释放。seek 不补播一路跨过的瞬时声，长尾/循环按目标时间恢复，正常前进的钟声事件只触发一次。

32 秒演出结束后保持末镜头，自然环境继续安静运行；不默认循环并突然让月亮、镜头和钟声复位。减少动态时保留手动选句/焦点、月落状态与可控声音，关闭强视差和显著摆动。

## 8. 真实三维与已有转场的接法

新增普通诗境页的场景宿主，复用引擎能力，不把生产路由导向 legacy 技术实验。宿主提供 prepare/firstFrame/enter/pause/seek/snapshot/exit/dispose；scene 接口保持 load/enter/update/exit/dispose 的职责。

入境流程：保留来源页 → 准备目标 DOM＋GLB＋贴图＋环境与着色器 → 渲染成功首帧 → 把同一个准备好的 Canvas 放入揭幕目标层 → 播放既有火缘 → 成功后提交 hash/正式开始 scene time。完成时移动/保留同一宿主，不因重新 render markup 销毁 Canvas再重建。音频不作为阻塞就绪条件。

退出流程：锁定当前 scene time/机位 → 明确重绘并捕获当前三维帧 → 快照图片替换 PageReturn clone 中的 Canvas → 同层 DOM 诗文/导航继续使用现有条带 → 翻页成功后释放场景并恢复总览位置/焦点。所有条带共享一份快照资源，不为 48 条带分别读回/编码。

快照首选专用 render target 的一次读取/转换，或同步重绘后的可靠 Canvas 截取；先在小样比较实际性能与色彩。不默认全程 preserveDrawingBuffer，不全屏截图 DOM，也不假设 cloneNode 能复制 Canvas。快照须与场景尺寸、裁剪、曝光和 DOM 对齐；捕获失败保留源页并允许重试/取消，不显示黑页。

资源所有权随导航事务转移；取消时释放准备资源，迟到的加载结果不能覆盖新场景。返回取消须恢复被冻结的画面/时钟和音频。Assets 当前 Promise 缓存不是完整生命周期管理，需明确共享船/纹理的引用计数，避免 dispose 掉仍在使用的资源或每次进入持续积累。

时钟统一复用 Clock：进入时记录 scene 时间原点，转场与自然系统用同一推进基准；现有独立 motion/legacy 循环不同时驱动同一场景。场景渲染器只在当前诗境/准备期间持有，转场结束释放效果层；不常驻三首完整渲染器。

## 9. 小样与成品验收

### 9.1 视觉证据

至少拍摄正向构图、近景木舟/石岸、掠射光、动态水面四类视角；机位都在 Blender 登记。浏览器固定 t=0/8/16/24/32，并密集采样渔火峰值、船体摆动极值、钟声抵达前后和反射更新；录连续短视频。调试可以切换法线/粗糙度/遮罩、反射/阴影/雾贡献，但最终证据使用完整效果。

- 石/木的表面与接合清楚，纹理尺度/木纹方向正确，无平面贴图冒充轮廓。
- 船与岸接触关系可信，阴影不浮离、无明显 acne/peter-panning；叶片阴影跟随摆动。
- 夜江是蓝灰低照度，暖火局部可辨；寺舟不沉成剪影，火芯不过曝成大片白块。先校准固定曝光/色彩，再调灯，不靠全局提亮或强 Bloom 补救。
- 倒影匹配物体与遮挡，月/火反光随波变化，水岸不穿模；雾片不过度遮舟桥寺，不在反射里出现不一致的层次。
- DOM 字体/竖排/对比度与诗文安全区通过；低档仍保留诗中关键意象。

Chrome DevTools MCP 检查真实 DOM/CSS、Console、Shader/网络错误、截图与性能追踪；Playwright 检查选句、Enter/Esc、取消、历史、收藏、reduced-motion。按本项目桌面范围验 1920×1080 与 1440×900，以及必要桌面缩窗；不新增移动设计。

### 9.2 性能与资源

既有硬门槛保持：场景全部压缩 GLB ≤15MB、单贴图≤2K、总 draw call <500；场景三角形建议≤1M、单近景物体建议≤50k、每首音频建议≤5MB。整包≤60MB仍是待赛事核实假设，新增贴图/环境图也要计入分发总量，不能仅报 GLB。

新增工作预算是提案，用于留下余量，不冒充已有性能：局部小样先以总 draw call ≤120、可见三角形≤200k 为工作目标；完整枫桥优先≤300 calls、≤700k可见三角形。统计包含阴影、倒影、后处理和转场效果，不能只算主 pass。高档 DPR=2 的既有 P0 设置不直接用于夜江，以 1920×1080/DPR=1 为统一基线，再测试高 DPR。

当前笔记本记录型号、CPU/GPU/内存、浏览器版本、实际绘制分辨率和 GPU backend。先预热，再连续测 60 秒并重复三轮；目标完整场景≥50fps，小样争取稳定60fps和P95帧间隔≤20ms，记录>50ms长帧、内存/资源峰值。DevTools 追踪与无追踪播放分开测，浏览器调度数据不冒称纯GPU耗时。

若小样只能勉强50fps，先缩反射RT/参与对象、透明重叠、阴影范围和DPR，重新验证画质，未留下余量前不扩建。最终指标必须在目标设备再验，不将当前笔记本或软件GPU结果外推。

连续进入/退出至少10次，检查几何/纹理/RT计数、监听/循环和内存是否回到可解释的共享缓存基线；稳定缓存允许存在，但不能随次数线性增加。测试冷/热缓存、缺失GLB/贴图、网络失败、加载中取消/快速再进、后台暂停和WebGL丢失/恢复；原生后台切换与模拟visibilitychange分别标明。

### 9.3 验证命令边界

运行端实现后从根执行 npm --prefix frontend run build、npm --prefix frontend test；有实际实现/失败夹具之后，check:contract/check:budget 才能作门禁。Blender validate/export/bake 使用已核实的显式可执行路径和统一脚本。资产优化须做前后结构比较与浏览器截图，不能只看文件更小。

本阶段专用证据放 docs/plans/R2-枫桥场景/assets，下属修订目录保留原始测量、失败诊断、时间码截图与视频；实际结果/限制写 HANDOFF，阶段结束再写 report。

## 10. 枫桥后再推进 R3/R4

江雪复用水/雾、舟构造、镜头和音频生命周期，但制作雪山雪岸、枯木、蓑笠翁/钓竿；积雪真实几何决定轮廓，材质决定表面。持续雪由固定种子实例/粒子分近中远层，承接风雪入境后降低密度；主体极静，保留孤舟与留白，衣摆只需轻微形变/少量确定性骨骼动作。

白帝城复用自然系统，重新制作峡谷轮廓、近景岩壁与可辨城轮廓。首版为精修有限长镜头，路径在 Blender 制作并登记导出引用，必要时扩展契约中的路径数据，不在 scene 中散写坐标。高远/深远来自地形尺度、雾和视差；晨光彩云、江流与左右猿声齐备，不做无限峡谷或强滚转。

R4 不再承担首次发现大问题的角色：性能/释放/许可随每阶段执行。R4 收敛目标机分档、字体/模型/贴图/音频逐项 CREDITS、无WebGL/静音回退、加载/断网异常、正常演示录音录像与离线启动。

离线包必须包含本地Meshopt/KTX2等所需解码器，不引用CDN。当前项目有真实登录门禁，离线交付要提供可在断网目标机启动的前后端/数据库及明确演示账号流程；Docker方案须预装引擎并预载镜像，准备干净机器演练。不能仅交frontend/dist或file://页面便宣称完整离线可用。比赛离线/包体/账号要求未定时，这一项保持外部待核实条件。

建议安排以关口为准：优先在10/6–10/8验证交接、小样和三维翻页，10/9–10/13收敛枫桥，10/14–10/18完成另外两首，10/19–10/22做最终目标机和交付。日期是工作窗口，不是承诺；小样或制作工具阻塞就重新估算，保留10/22冻结。优先压缩无限峡谷、全场体积云雾和额外装饰，不能默默删三首意象或发布空场景。

## 11. 官方依据与版本限制

- PBR通道和纹理语义依据 [Khronos glTF 2.0规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html?ld=SDINSOADirect)；色彩管理依据 [Three.js官方说明](https://threejs.org/manual/pages/color-management.html)。

## 12. 2026-10-07 修订：侧舷划桨与其余夜景元素

### 12.1 舟体修正的制作约束

用户最新要求以**侧舷划桨**为准：支点位于船侧舷缘上方，外侧桨杆向船侧水面伸出，不从船尾跨出。保留人体蒙皮与掌部接触点，重新制作桨柄折线、支撑榫和桨叶方向，并按新支点重新校准横扫、扭桨与等长牵绳；不只平移一个装饰桨。船壳使用连续底/侧面及两端封板，带实体厚度；乘员舱顶部仍开放。

交接增加 `boat_hull_closed` 必需网格，属于 `boat_guest`。Blender 校验实体边，GLB 校验按位置焊接 UV/法线分裂顶点后每条三角边恰好共享两面；删面、错父级必须失败。浏览器重放完整 4.8 秒循环的 97 个真实局部桨变换，检测实际桨杆、桨柄、桨叶三角形与连续船壳/木构件相交，另用故意插入船壳的阳性夹具证明检测有效。支撑榫、绑扎和牵绳为设计接触，不纳入活动桨与船壳检查。离散几何检查配合连续录像、侧舷和首尾视角目视检查，不宣称连续碰撞求解或整个人物接触面已验证。

首帧准备采用离线保存固定夜空的预滤波 RGBA16F CubeUV 原值，再在浏览器恢复相同过滤/色彩空间；原程序环境作为独立像素基线，不能以降低天空、水倒影或阴影分辨率换取通过。离屏阴影、倒影与屏幕着色器按各自输出环境预编译。该格式绑定 0.186.1；Context7 的 dev 迁移文档已提示 187 改变 PMREM 结构，因此不升级版本或跨版复用。静态环境预算、损坏/缺失、HTTP自动解压/原始gzip和退出释放一并校验。

| 4. 月落、薄雾与夜景联调 | 全局 t 驱动月亮位置/亮度、细波/倒影、舟水线、低频渔火。高度/距离雾加少量局部雾片；倒影选择寺桥舟轮廓，限制透明层重叠 | 月落末态不复位；薄雾有深度而不盖住舟桥；暖火有实际照明，暗部可读。每增加一类效果都验固定帧与性能 |
| 5. 诗句镜头、钟声与真实三维转场 | 按第 7 节完成 32 秒演出、钟声传播与暂停/seek；按第 8 节把准备好的同一 Canvas 接火烧入境，把冻结的三维帧接翻页 | 正常诗境页面完整闭环，入境无黑帧、返回快照匹配当前机位，取消/迟到加载/释放正常；音频实听与静音/减少动态通过 |

复杂建模采用“参数化骨架＋有结构的可见几何＋高模烘焙＋浏览器复查”。雕刻磨损只进入近景高模和法线/粗糙度，不能用贴图代替首尾封板、檐口或桥拱。自然系统保留在 `systems`/`shaders`，场景文件只装配和编排。

完整场景压缩预算先提案为舟/人体共享资产 ≤5MB、寺桥 ≤5MB、岸/植被 ≤3MB、余量 2MB；分 GLB 仍按全场总和统计，目标值须经压缩实验确认。贴图最大 2K，优先 1K 共享材质；法线/ORM 不无条件转有损图片，KTX2 若需要须另验证离线解码和画质。完整场景继续以 ≤300 多 pass calls、≤700k 多 pass 三角形作为工作预算，当前笔记本 1920×1080/DPR1 三轮 60 秒 ≥50fps、P95≤20ms，并做十次加载/释放。未过枫桥完整关口不进入另外两首。
