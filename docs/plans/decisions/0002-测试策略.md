# 0002 · 测试策略

- 状态：采纳
- 日期：2026-09-28

## 背景

项目以渲染为主，画面对错很难用断言表达；但全局时钟、随机数、高度图解码、钟声延迟等是纯函数，写错了会悄悄污染所有画面。工期只有 25 天，测试必须便宜、能自动跑。

## 决定

三层验证：

| 层 | 工具 | 覆盖 |
|---|---|---|
| 纯函数 | vitest（`npm --prefix frontend test`） | 带种子随机、全局时钟、URL 参数解析、高度图解码、波纹公式、分镜时间换算等。**先写测试再写实现** |
| 渲染 | Playwright（`frontend/tools/shoot.mjs`） | 通过 `window.__POETIC__.seek(t)` 跳到固定时间码截图；同一时间码两次截图逐像素一致（可复现）；关键帧截图进验收报告 |
| 资产 | `art/scripts/validate.py`（Blender 端）+ `frontend/tools/check-contract.mjs`（运行端） | CONTRACT 第 15 节 |

- 截图基准不入库做像素级回归（画面在 P2 前会频繁改），只作为验收证据放进 `docs/plans/<阶段>/assets/`。
- 帧率在目标笔记本上人工测，结果写进阶段报告。

## 备选及放弃理由

- **全面像素回归**：美术调整期间基准天天变，维护成本高于收益。等 P6 冻结后再考虑。
- **只靠人工看**：无法发现"跳转后结果不一致"这类问题，而它会破坏 `?t=` 跳转、录制和答辩时的数字键跳幕。

## 影响

- `frontend/package.json` 引入 vitest 与 playwright。
- 所有动画必须是 f(t)，否则无法通过"同一时间码截图一致"的检查。
