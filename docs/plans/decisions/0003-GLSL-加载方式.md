# 0003 · GLSL 加载方式

- 状态：采纳
- 日期：2026-09-28

## 背景

着色器按 `frontend/src/shaders/{chunks,materials,postfx,sim}` 拆分（设计文档 23.2），材质着色器需要引用 `chunks/` 中的公共片段（noise、fbm、paper、inkReveal、ripple、triplanar）。Vite 原生的 `?raw` 只能把文件读成字符串，不处理 `#include`。

## 决定

使用 `vite-plugin-glsl`：

- `import frag from './water.frag.glsl'` 直接得到字符串；
- 支持 `#include "../chunks/noise.glsl"`，并对重复引用去重；
- 生产构建时压缩着色器代码。

`onBeforeCompile` 注入到 three.js 内置材质的片段，同样以字符串形式从 `.glsl` 文件导入。

## 备选及放弃理由

- **`?raw` + 自写 include 解析**：约 20 行代码，但要自己处理相对路径、去重和热更新，没有必要。
- **全部写成 TS 模板字符串**：失去编辑器的 GLSL 高亮与检查，片段复用靠字符串拼接，易错。

## 影响

- `frontend/vite.config.ts` 注册插件；`frontend/src/` 下需要 `*.glsl` 的类型声明。
- vitest 也要加载同一插件（共用 `frontend/vite.config.ts`）。
