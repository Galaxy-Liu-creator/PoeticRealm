## 1. 项目名称

**诗境 · 一卷山河** / Poetic Realm · A Scroll of Mountains and Rivers。

## 2. 项目定位

以中国古典诗词为入口的交互式三维山水作品：**先看见诗词全貌，再选择一首进入其意境**。首页是有动态山水背景的诗词总览，不再是黑屏印章或三维书房。

核心体验：浏览浮动诗词卡片 → 按诗中意象平滑入境 → 在真实、有质感的山水中读诗、观景、听声 → 收藏 → 翻页返回总览。

不做游戏、商城或普通图片阅读器。首页可以是二维 UI 与动态背景的组合，但诗境主画面必须有真实的三维空间、材质、光照与环境动态。

## 4. 设计原则

1. **诗境优先**：水、雪、火、山、舟、寺服务具体诗意，不堆叠无关奇观。
2. **真实质感，东方构图**：真实尺度和材料关系，保留平远 / 深远 / 高远、留白与书法；不以全屏纸纹或强描边掩盖粗糙模型。
3. **动静有别**：首页缓动，转场短促可控，诗境动态依诗而异；诗文与操作区始终可读。
4. **入口明确**：用户打开就能选择诗，不被长片头阻挡。
5. **设计先行**：生成稿通过审批后才细化实现；静帧审批不代替动态和真实性验收。

## 5. 视觉方向（提案）

推荐 **“青黛山水 · 写实诗境”**：主页与收藏页以用户指定 v09 原图为准，结合全宽青黛山水题头、绢纸山影与竹叶、对齐诗卡和书签装饰。新图取代此前 v08 云雾减法提案，后续按原图还原，不用霓虹光束。

其他方向的取舍：继续纯水墨容易重复当前缺少材质层次的问题；玄幻高饱和国风容易变成仙侠游戏界面。因此以写实环境为主体，书法与山水构图提供中国文化辨识度。

配色、卡片比例、边角以当前推荐原图和 R1 契约为准；最终字体、动态强度与浏览器视觉仍需验收。

## 6. 页面与导航流程

### 6.1 页面地图（采用 hash 路由，便于静态与离线部署）

| 路径 | 页面 | 顶部返回 |
|---|---|---|
| `#/` | 诗词总览 | **不显示** |
| `#/poems/<id>` | 对应诗词展示页 | **显示；翻页返回总览** |
| `#/favorites` | 我的收藏 | 显示 |
| `#/profile` | 个人中心 | 显示 |
| `#/account` | 全屏幕布账号入口，宣传语与登录 / 注册 | 闭幕参考构图，无强制导航条，提供回总览 |
| `#/login` | 登录 | 页内登录/注册切换、深色模式与返回首页 |
| `#/register` | 注册 | 同上；桌面完整表单一屏展示 |

顶部导航属于网站内的导航，不是修改浏览器工具栏。总览、收藏、个人中心与诗境共有“诗词总览 / 我的收藏 / 个人中心”，非首页增加返回；诗境额外提供“收藏本诗 / 已收藏”，与前往收藏列表区分。登录/注册采用 v10 的页内切换和返回首页，幕布入口采用 v07 全屏构图。

### 6.2 核心流程

打开网站 → 直接显示总览和全部已收录诗词 → 点击卡片 → 加载必要资源 → 意象转场 → 诗境与诗文 → 翻页返回原总览位置。

收藏页点击诗词同样进入诗境；诗境内的返回始终回总览，不因从收藏页进入而改变。个人中心和收藏页返回上一个有效站内页面，无站内记录时回总览。

浏览器后退 / 前进与网站路由统一处理，不产生二次跳转或历史死循环；从诗境后退到总览也使用翻页。直接打开诗境链接仍应有返回和加载态，不能要求先访问首页。

账号入口是独立流程，不改变默认总览入口：全屏闭幕 → 点击登录或注册 → 对应表单与画面准备就绪 → 双幅幕布向两侧拉开 → 显示目标页。幕布沿用 [v07 用户参考](design/2026-10-01-v3/v07/README.md)，目标表单改用 [v10 用户新图](design/2026-10-01-v3/v10/README.md)；最终布面细节与视觉复审仍见 R1 报告。

### 6.3 状态与异常

加载中保留来源页面，卡片显示真实加载状态；目标资源就绪且首帧成功渲染后才进入揭幕。失败显示重试 / 取消，不烧出黑屏。转场期间只接受一次导航；返回或取消会取消未完成加载和音频安排。

不存在的诗词显示“未找到这首诗”和回总览；开发中未就绪场景标为“制作中”，不得点进去进入空画布。最终交付的收录卡片必须对应可进入场景。

## 7. 首版诗词

| 诗词 | 主题色与质感 | 入场提案 | 重点 |
|---|---|---|---|
| 枫桥夜泊 · 唐 / 张继 | 蓝灰夜江、湿石、木舟、局部暖渔火 | 中央纸面燃开，克制余烬 | 月落、江枫、寒山寺、钟声到客船 |
| 江雪 · 唐 / 柳宗元 | 银灰雪山、冷青江水、细雪与蓑衣 | 右上向左下的广域碎雪覆盖再揭幕 | 极静的山江与一舟一人 |
| 早发白帝城 · 唐 / 李白 | 青绿峡谷、真实岩壁、朝霞与江流 | 云雾 / 水光揭幕 | 轻舟、峡谷纵深、两岸猿声 |

火烧对应“渔火”，是页面意象而非寺庙或山林失火；用户可在审批中调整为更弱的火缘效果。所有诗词可以配置独立转场，不强制全用火或雪。

## 8. 《枫桥夜泊》诗境

> 月落乌啼霜满天，江枫渔火对愁眠。姑苏城外寒山寺，夜半钟声到客船。

- **Blender 主体**：唐风寺与钟楼、枫桥、客船与渔舟、近景枫树 / 芦苇、河岸关键轮廓。
- **程序化自然环境**：江面反射与细波、薄雾、月相和夜空、少量落叶、渔火闪烁、植被轻摆。
- **材质标准**：石岸有粗糙度层次与接缝；木舟有构造和木纹方向；寺院有可信屋檐、台基、梁柱；不可用发光轮廓代替细节。
- **构图**：主景占屏幕大部，诗文置左上安全留白区；江面、桥和寺保持前中远三层。低照度不等于全画面黑。
- **文化边界**：保留月落的时间变化；“霜满天”表现寒意，不当作密集降雪；建筑唐风，不冒充寒山寺历史原貌的精确复原。
- **钟声“到”**：沿用从寺前到客船的意象化波前，距离从 GLB 节点计算，传播时长 = 距离 / 340 m/s。抵船时响钟；它是声传播的艺术可视化，不声称真实水波以声速传播。当前灰模距离约 956.4 m，只是既有测试值。

## 9. 《江雪》诗境

> 千山鸟飞绝，万径人踪灭。孤舟蓑笠翁，独钓寒江雪。

- 山势、孤舟、蓑笠翁、钓竿、雪岸和近景枯木需要可信结构；舟可复用但积雪、材料与摆动参数要匹配。
- 程序化雪、雾、细微水动与衣摆；留白由空间、雾和低对比远山形成，不是铺满纯白。
- 雪覆盖入场结束后回落为克制的持续降雪；要看见细碎雪花、前后层次和整屏分布，不只是右上角几个雪花图标。
- 可在左上或右侧留白安置竖排诗，不能遮住孤舟；声音逐渐减弱，突出静与孤。

## 10. 《早发白帝城》诗境

> 朝辞白帝彩云间，千里江陵一日还。两岸猿声啼不住，轻舟已过万重山。

- 岩壁与峡谷尺度可信，山体不做低多边形尖锥；白帝城只保留可辨识的唐风远景轮廓，细节服从预算。
- 江流、云雾、朝霞和远景植被由可复用系统生成；自然参数不放入场景组装文件中散写。
- 速度感来自两岸视差、江流和左右猿声，不滚转、不甩镜头。
- 首版仍建议采用一段精修长镜头，不承诺无限峡谷、体积云和复杂建筑群；不能因此省掉诗中彩云与城的视觉提示。

## 11. 首页：题头与诗词总览两个区域

### 11.1 上部题头

- 网站导航之下是一条明显较暗的宽幅山水题头，而不是占满全屏的等待页。
- 核心标题精确为 **“诗境·一卷山河”**，使用真正有行书笔意的标题字形；不能用普通楷体或生成乱码冒充行书。
- 背景有层叠山影、流动江水、薄雾与柔和反光；标题后保持低对比安全区。背景铺满整个上区至视口左右边缘，不留平色侧条；文字与导航仍保留内容内边距。
- 桌面初稿建议题头约 280–340 px，高度需保证首屏看得到诗词卡片。标题与下面的“诗词总览”有明确层级。

### 11.2 下部资产总览

- 对用户显示“诗词总览”，不是技术用语“资产库”。
- 以用户最新指定的 [v09 主页原图](design/2026-10-01-v3/v09/screens/S01-home-desktop-user.png) 为准：绢纸底景、浅色山影、水面、竹叶及云纹装饰按图还原。此选图取代 v08 的中央不出现山河提案；保持三卡等高齐平与全宽题头，不再自行删减原图元素。
- 三首诗用三张大卡片呈现，不做空旷的十几张假内容网格。增加内容后自然扩展网格。
- 背景可参考有明确来源的中国山水作品，正式使用须逐项核对许可；不从搜索结果随意复制背景进 `frontend/public/`。

## 12. 浮动诗词卡片

- 2026-10-01 用户认可现有 Desktop 风格，并进一步明确三卡不要错落：外框等宽等高，顶部、底部、封面分界、标题和入境按钮对齐；取消中卡抬高。长诗名不得撑高卡片，浮动不改变尺寸或缩放。
- 卡片有不同诗境的预览画面、诗名、朝代作者、代表诗句、收藏控件和清晰的进入指示。
- “浮动”保留稳定网格与层次阴影。若使用上下缓动，三卡必须同相同幅同步移动，始终等高齐平，不出现错落；具体幅度周期待动态验收。
- 悬停或键盘聚焦任一卡时整组三卡停稳，强调可点击区域。
- 进入和收藏是独立交互，收藏不触发进入；不能把按钮非法嵌套在链接内部。
- 首页只运行一套背景渲染，不给每张卡片同时开一个完整 3D 场景。

## 13. 转场：按意象入场，翻页出场

### 13.1 共通契约

转场由来源帧、目标帧、进度 `p∈[0,1]`、固定种子和配置描述。`p=0` 为完整来源，`p=1` 为完整目标；中途不得出现空帧、丢失的导航或不受控闪白。

### 13.2 火烧揭幕

从页面中央出现不规则开口，焦边和短促暗橙余烬向外扩展，开口内逐渐显示目标诗境。强调“纸面烧开”，不是全屏爆炸或高亮传送门；诗文在目标已可读后出现。建议 1.4–1.8 秒。

### 13.3 风雪覆幕

雪由右上方向左下跨越整个视口，密度逐步增加；**粒子层 + 连续的柔和雪雾遮罩**完成覆盖，避免只靠稀疏粒子时底层突然切换。覆盖后显露江雪，雪从转场强度过渡到场景强度。建议 1.8–2.4 秒。

### 13.4 云水揭幕

白帝城以流云或水光缓慢揭开，不强贴火雪意象；其他诗词将来通过配置选择已有转场或新增专属转场。建议 1.2–1.8 秒。

### 13.5 翻书返回

诗境“返回”将当前画面作为纸页正面，从左向右翻起，露出诗词总览；须有卷曲、背面与柔和阴影，不能只做水平滑出。建议 0.9–1.3 秒。总览恢复滚动位置及触发卡片焦点。

### 13.6 DOM 与画布边界

火、雪与翻页需要统一的屏幕合成层。设计中必须验证 DOM 诗文、导航、卡片与 WebGL 的遮挡关系；不能假设 WebGL 会自动捕获 DOM。实现前做专门小样，比较“Canvas 画面翻页 + 同步 DOM 遮罩”与完整快照方案，后者需验证字体、跨域、性能和文字清晰度。首页返回背景须提前就绪。

### 13.7 尺度与旧方案

新版不再要求把世界缩到书页大小，也不强制 PaperToWorld。世界继续按 CONTRACT 的米制构建。PaperTerrain / InkSim 留作实验和可复用模块，旧有 RG 高度图与 B 引导遮罩不删除、不改编码。

### 13.8 时序与验收

[STORYBOARD.md](STORYBOARD.md) 记录关键进度帧。设计稿的 0 / 25 / 50 / 75 / 100% 分镜是视觉提案，不等于真实效果已跑通；实现后由全局时钟和 Playwright 验证。

### 13.9 降级

减少动态效果或设备低档时，保留同一导航语义，改为短淡入淡出 / 静态纸页替换。目标未就绪时显示加载 / 重试，不延长燃烧或积雪循环伪装加载。

### 13.10 旧 InkWipe 的定位

不再是所有诗词切换的强制方式；可以作为未来某首水墨主题的可选入场，但不是新版验收底线。

### 13.11 账号入口拉幕

账号入口大舞台幕布覆盖整个页面，中央宣传语下有登录与注册按钮。R1 已实现 1.2 秒双幅外移、文案淡出、目标解码准备、输入锁定、焦点、加载失败恢复与后退取消；减少动态直接切换。使用浏览器 Animation 时间轴与可定位 currentTime，不新增持续 RAF；标签页隐藏时暂停。完整布面收拢、合成与场景全局时钟衔接留待后续；原始规范见 [T05](design/2026-10-01-v3/v07/curtain-transition.md)。

## 14. 渲染方案

### 14.1 不变的技术底座

WebGLRenderer + GLSL，现有 three.js 精确版本不升级。GSAP、骨骼、自然环境和 UI 持续动画最终都受同一全局时钟驱动。

### 14.2 写实基础

以可信光照、粗糙度、法线细节、材质尺度、接触阴影和反射关系建立质感。不是单纯加曝光、Bloom 或提高面数。材质应在目标浏览器中验收，不把 Blender 离线渲染当作实时效果证据。

### 14.3 风格化的边界

调色与少量局部书画质感可用；不再默认全屏 Kuwahara、量化墨色、粗描边或重纸纹。夜景、水雪、晨峡分别调色，保持自然细节。

### 14.4 雾与留白

雾有真实空间层次，色彩依场景而定，不强制渐隐为纯纸白。文字区域通过构图和局部背景处理保障对比度。

### 14.5 自然环境

水、天空、雾、云、雪、风和远山细节可用 JS / GLSL 程序化生成；近景岩岸、重要地貌轮廓优先由 Blender 控制。程序化代码集中在 `systems/` 与 `shaders/`。

### 14.6 资产迁移关口

现行 CONTRACT v0.1 只约定 Base Color / 贴图和水墨槽位，并未承诺读取完整 PBR 贴图。写实材质需要的 roughness / normal / AO 等资产输入，应在实现阶段先形成 CONTRACT v0.2 变更，再同步校验、导出、加载与资产；本轮不偷偷修改契约或假装它已支持。

### 14.7 预算

优先控制阴影、透明层、屏幕合成和水面反射成本；按需加载当前诗境，转场最多短时持有两个渲染目标，不常驻三套完整场景。

## 15. 镜头系统

### 15.1 模式

Cinematic（按诗句演出）、Orbit（受限观察）、Focus（点击某句诗转向焦点）；自动 Guided Tour 不列入首版。

### 15.2 机位来源

诗境机位来自 Blender `CAM_`，焦点来自 `FOCUS_`，不得在场景代码中写死坐标。二维 UI 的 CSS 排版和全屏合成用的正交坐标不属于诗境机位。

### 15.3 三远

保留 `yuan: gao / shen / ping`：枫桥与江雪以平远为主，峡谷强调高远、深远。诗文安全区需要在 Blender 构图时一起考虑。

### 15.4 舒适性

无滚转、限制角速度，减少动态效果时关闭强视差、全屏风雪和快速穿峡；触控不以晃动设备作为唯一操作方式。

## 16. 诗文、目录数据与分镜

- 文案仍放 `frontend/src/content/poems/<id>.json`：稳定 id、诗名、作者、朝代、逐句原文、注释、译文、意象与考据。
- 新增目录元数据的目标：封面引用、展示顺序、入场类型、场景就绪状态；具体 schema 在 UI 审批后定义，不能把“占位”标成“已收录可进入”。
- 演出仍在 `frontend/src/scenes/<id>/timeline.ts`，引用 GLB 机位 / 焦点，不把 UI 收藏状态塞入场景。
- 诗文采用竖排 `writing-mode: vertical-rl`，右起；左上定位不改变列阅读顺序。当前三首按四列完整展示；白帝城四列各七字，等宽等列距、顶底齐平，参照枫桥节奏；不能使用一对紧挨、另两列远离的排版。
- 保留全局可跳转时钟、带种子随机、`?scene=<id>&t=<秒>`、`?q=`、`?debug` 和 `window.__POETIC__`；现有调试参数与新 hash 路由的优先级将在实现计划中明确，建议显式调试 scene 覆盖普通路由。
- 所有动画是 `f(t)`；禁止 `Math.random()`、`Date.now()`、`performance.now()` 驱动画面。非纯函数仿真按固定步长，seek 从 0 重建。

## 17. 音频

首页默认静音，不用黑屏点击门禁解决音频权限。点击卡片或声音开关后请求解锁；拒绝或失败也能继续看诗境。

保留环境、音效、人声、音乐分轨；诗境退出后淡出并释放。翻页、火缘、雪风的音量不得盖住诗词朗读。钟声、乌啼、两岸猿声仍与意象和镜头绑定；循环、暂停、跳转与全局时钟对齐。

## 18. Blender ↔ 代码契约

数据契约以 [CONTRACT.md](CONTRACT.md) 为准：米制、节点 / 材质名、`userData`、`mask`、`PLACE_`、高度图编码、相机、预算均维持现行有效规则。

产品体验由本文规定；CONTRACT 中提到旧书房、纸面隆起或水墨材质的说明属于现有资产接口背景，不要求新版继续旧流程。需要修改材质输入、地形来源或必需场景清单时：**CONTRACT → 校验脚本 → 资产与代码，同次提交**。

R1 UI 不新增资产契约字段或材质槽位，不更名 GLB，不修改导出参数。

## 19. 资产制作流程

Blender 建模 / 程序化制作 → 制作端校验 → GLB / 高度图导出 → Meshopt 与贴图优化 → 契约 / 体积检查 → Three.js 实机验收。

- `.blend`、源贴图和源音频仍在 `art/`；发布产物在 `frontend/public/assets/`。
- 有真实构造的寺、桥、舟、人物和近景植被由 Blender 生产；不在 `scenes/` 临时拼几何代替。
- 自然环境可以代码生成，但若要更换 CONTRACT 规定的高度图输入，仍需先走契约迁移。
- UI 生成图保存在 `docs/design/`，审批和许可核验之前不进入 `frontend/public/`。

## 20. 界面、收藏与个人中心

### 20.1 字体与色彩

当前以用户新增的 [字体规范](字体规范.md) 为准：品牌与幕布主标题使用行书；页面、章节、卡片标题和主按钮使用宋体；诗文、宣传语、副标题与签名使用文楷；导航、表单、数据、设置和次级操作使用黑体。统一通过 `--font-brand / --font-serif / --font-kai / --font-sans` 及四种语义类分配，页面标题 700、章节/卡片及主按钮 600、标签 500、正文 400。字体只引用本机已安装字体，宋体/黑体优先 Noto SC，文楷缺失回退楷体；无远程字体下载与异步换字形。正式嵌入需核实许可。运行时文字均为 DOM，背景和页面结构不改。

建议颜色：青黛、青灰、绢色、远山绿，少量朱砂用于收藏状态；不用金红宫廷、赛博光束、玻璃卡片或发光大按钮。

### 20.2 诗境 UI

薄而清楚的顶部导航、留白处诗文、可收起的注释 / 译文、收藏本诗与声音控制。诗境至少占主要可视面积，不用大侧栏挤成模型预览窗口。

### 20.3 收藏页

以用户指定的 [v09 收藏页原图](design/2026-10-01-v3/v09/screens/S05-favorites-desktop-user.png) 为视觉基准，替代旧 Stitch S05；返回总览、绢纸山水、收藏书签、取消收藏与入境按图还原。图中两卡是示例，显示真实收藏数量，无等级、积分、排行榜。空状态提供“去总览选一首诗”；取消收藏后立即更新，持久化失败应明确提示，不假装保存成功。

### 20.4 个人中心（用户原图替代旧 Stitch）

- 以 [S06 用户原图](design/2026-10-01-v3/v07/references/S06-profile-user.png) 为后续开发视觉基准。旧 Stitch S06 不再是推荐稿，原文件保留历史。
- 全宽山水题头；左栏圆形头像、昵称、摘要与账号信息；右栏收藏、最近浏览、成就与偏好、系统设置，严格遵循原图比例、纸面和层次。
- 原图昵称、邮箱、数量、时间、成就与开关为示例；实现使用真实数据，不伪造浏览次数、收藏量、解锁进度或通知服务。资料编辑能力在该构图中另设编辑状态，不恢复旧大表单布局。

- 头像：默认原创占位头像，可本地选图、预览 / 裁切、确认、更换、恢复默认；不自动上传到第三方。
- 姓名：去除首尾空白，建议 1–24 个字符；允许中文，不把它当实名校验。
- 性别：可不填，提供“未设置 / 女 / 男 / 自定义”，只作个人资料，不推断其他信息。
- 展示已收藏诗词，可直接进入；保存、取消和错误反馈明确。
- 头像仅接受可解码的 JPEG / PNG / WebP，建议输入 ≤ 5 MiB 且 ≤ 1600 万像素；拒绝 SVG 和伪装格式，重采样为 256×256 并去除原图元数据。
- R1 使用版本化 localStorage 存小规模资料、256px 重采样头像与收藏 id；不存密码或对象 URL，不声称跨设备同步。写入异常退化到会话并清楚提示，刷新后仅在持久化成功时保证保留；后续大文件或云同步再迁移。
- 收藏、资料与渲染分离；数据不驱动画面随机。测试用虚拟资料，不把用户真实头像传给设计工具。

### 20.5 登录 / 注册与幕布入口

用户新供 [登录 v10](design/2026-10-01-v3/v10/references/S11-login-user.png)、[注册 v10](design/2026-10-01-v3/v10/references/S12-register-user.png) 原样保存，替换旧 v07 账号图。两页采用左侧青黛山水与右侧曲线白面，表单直接置于留白，无旧绢纸卡片或侧幕；登录四项体验、注册三项体验。两页均有中英双语切换、月亮主题按钮及返回首页。欢迎回境/创建账号、字段与按钮按新图排布，字体按第20.1节的四种语义角色与字重设置，桌面按宽高缩放保证一屏显示。

## 21. 文化与考据

保留原诗原文、作者朝代、注释与译文，避免 AI 生成图中错字进入发布版。建筑参考唐风结构；山水可借鉴董源的层次、马远的留白和青绿山水的色彩组织，但**参考构图不等于直接复制画作贴图**。

月相与作诗时间有解释空间，不能把某种舞台化方案标成唯一历史事实；钟声可视化、天色压缩等艺术处理在说明中注明。

## 22. 技术选型

继续使用现有原生 TypeScript UI + Three.js；不因新增几页就更换框架。新增路由与本机存储保持独立模块。GSAP 时间线暂停并由全局时钟 seek；复杂主体用 Blender，环境系统与后处理用 GLSL。

前端保持现有框架及 three.js 版本；后端采用 Spring Boot，独立 Maven 工程，通过 /api/v1 与前端通信。创建配置与认证边界见架构规划；本轮只迁前端，不生成或接入后端。

## 23. 目标架构与目录

仓库顶层使用 frontend/backend 两个独立工程，art/docs 保留根目录。backend 尚待用户创建，前端运行 UI 图片副本放 frontend/src/assets/ui，不再导入设计归档；原稿和来源仍在 docs。后端包与接口规划见 [架构文档](architecture/前后端分离与认证规划.md)。

| 层 | 职责 |
|---|---|
| `frontend/src/app/` | 路由、导航事务、流程状态、场景生命周期 |
| `frontend/src/ui/pages/` | Home / Poem / Favorites / Profile / AccountEntry / Login / Register |
| `frontend/src/ui/components/` | 导航、诗词卡片、竖排诗文、头像选择、加载与错误态 |
| `frontend/src/ui/styles/` | 字体、颜色、间距、响应式 |
| `frontend/src/stores/` | 本机资料、头像、收藏与存储失败处理 |
| `frontend/src/content/` | 诗文与目录元数据 |
| `frontend/src/transition/` | R1 CurtainReveal；FireReveal / SnowReveal / CloudReveal / PageTurn 在 R2/R3 实施 |
| `frontend/src/scenes/` | 诗境组装、分镜、配置，不建模 |
| `frontend/src/systems/` | 地形、水、天空雾云、粒子、镜头、声音、材质、行为 |
| `frontend/src/engine/` | renderer、全局时钟、加载与释放、画质、调试 |
| `frontend/src/shaders/` | 公共片段、材质、合成转场、后处理、仿真 |
| `docs/design/` | 混合版本视觉清单、brief、参考来源、原始生成稿、审批记录 |
| `frontend/src/legacy.ts` | 独立保留 P0 实验，显式查询调试参数进入 |

SceneManager 保留 load / enter / update / exit / dispose 边界。路由只在加载与揭幕成功后提交目标状态；导航事务负责取消旧请求，清理对象 URL、监听、粒子、音频和渲染目标，避免返回数次后持续增长。

## 24. 性能与降档

首页一个轻量动态背景 + 静态卡片封面；非可见页面不继续跑高成本场景。桌面较低性能档可降低粒子数、雾层、反射和阴影，保留导航 / 表单。减少动态效果覆盖 UI 卡片、背景、转场和镜头。

设备性能目标必须在目标机器实测；AI 图中的光照、云雾和细节不是性能承诺。夜景黑、雪景白、透明粒子叠加是重点检查项。

## 25. 响应式与可访问性

- 设计稿覆盖桌面网页；以 1440px 宽为主要排版基准，兼顾桌面窗口缩放，运行时另验 1920×1080。移动端不在本轮范围。
- 导航 / 卡片 / 收藏 / 表单可用键盘。按用户要求，所有输入控件聚焦不显示外框或阴影，文本输入保留光标；按钮与链接保留可见键盘焦点，有中文可访问名称和清楚的点击区域。
- 正文与背景对比度目标 ≥ 4.5:1；诗文在亮雪、夜江、火烧前后都要检查。
- 长诗分组保留 DOM 逻辑阅读顺序；装饰性重复文字不重复朗读。
- 无 WebGL 时仍能看目录、诗文、收藏与个人资料；用经许可的静态预览和提示代替空白。

## 29. 范围取舍

优先减少无关装饰、体积云 / 高成本反射、无限峡谷、深度文化面板和自动导览；不恢复强制长片头。不能擅自砍掉用户要求的总览、平滑意象入场、诗境翻页返回、收藏与个人资料，也不能用粗模充当“真实建模”。若三首无法达标，要向用户说明并请求调整范围。

## 30. 禁止事项

- 不做纯黑 / 纯白首页，不把流光做成赛博霓虹，不伪造收藏、账号或收录量。
- 不做游戏 HUD、等级、商城式卡片、玻璃拟态、发光大按钮、龙凤祥云和宫廷金红。
- 不用全屏后处理遮掩模型质量，不把 AI 概念图当作成品效果。
- 不强制旧书房和纸面生长流程，不无过渡切到空场景。
- 不改渲染技术栈，不散写机位，不绕过资产契约与许可；仅在当前授权范围实施。

## 32. 审批与演示顺序
