## 1. 项目名称

**诗境 · 一卷山河**

英文名：**Poetic Realm · A Scroll of Mountains and Rivers**

---

## 2. 项目定位

《诗境 · 一卷山河》是一款以中国古典诗词为核心内容，通过 Three.js 三维场景、程序化动画、水墨视觉效果、环境音效与交互式镜头，将古典诗词中的文字意象转化为可探索三维空间的交互式数字文化作品。

项目不以"阅读古诗"为核心，而是尝试实现：

> **让诗句不只是被读出来，而是被看见、被听见、被进入。**

用户不是单纯阅读诗词，而是从一张中国传统书案进入古籍，在选择诗词后，看到毛笔在纸上写下诗句、墨迹在宣纸上洇开、山体从纸面隆起、江河从留白中生成、树木与建筑以墨色显现，最终整张书页成为一个完整的三维诗词世界。

整个项目希望实现：

**诗词 → 意象 → 场景 → 氛围 → 情绪**

的完整视觉转化。

## 4. 核心设计理念

### 4.1 不是"古诗词阅读器"

禁止将项目设计成：

- 普通古诗网页
- 古风 UI + 文字展示
- 单纯翻页电子书
- 图片背景 + 诗词文字
- 普通 3D 模型浏览器

项目核心必须是：

> **诗词意象的三维空间化。**

### 4.2 让诗句驱动场景

诗词不是 UI 装饰，而应参与场景逻辑。每一句诗对应一段分镜（机位、焦点、效果、声音），由统一的分镜执行器播放（见第 16 章）。

例如《江雪》：

| 诗句 | 触发 |
|---|---|
| 千山鸟飞绝 | 远处飞鸟逐渐消失，天空趋于安静，镜头拉远 |
| 万径人踪灭 | 山路被雪逐渐覆盖，人迹消失，雾气增强 |
| 孤舟蓑笠翁 | 镜头穿过雾层，江面出现孤舟，蓑笠翁逐渐显现 |
| 独钓寒江雪 | 雪势增强，镜头停留在孤舟，环境音减弱，完整诗境形成 |

三首诗的逐句演出见第 8–10 章。

### 4.3 强调中国文化本身，而不是"古风皮肤"

中国文化表达应该来自：

- 古典诗词
- 中国山水画的构图与笔法（留白、三远、皴法）
- 宣纸、水墨、书法、篆刻
- 唐风古建筑
- 江南水乡、山川、舟船、寺庙
- 古琴、钟声、猿啼等声音意象
- 中国式留白

避免无意义堆砌：

- 龙、凤、祥云
- 大面积金色、宫廷红
- 明清彩画
- 游戏式古风 UI
- 过多复杂花纹

整体视觉应偏向：

**文人气、山水气、留白、雅致、克制。**

## 5. 核心视觉概念

> **一页纸，生出一片山河。**

整个项目最关键的视觉演出不是场景本身，而是：

```text
二维宣纸
↓
毛笔写下诗句
↓
墨迹在纸上洇开
↓
墨迹汇成山水轮廓
↓
纸面出现起伏，山体隆起
↓
江河在留白处形成
↓
树木、舟船、建筑以墨色显现，再染上场景色
↓
镜头下降，从俯视书页变成进入山河
↓
完整三维诗境
```

这是整个项目最核心的视觉记忆点。技术上由三个"统一"实现（详见第 13 章）：

- **一张网格**：书页和地形是同一张网格，纸就是地。
- **一张遮罩**：墨迹遮罩同时控制高度、颜色、水面和物体的显现。
- **一镜到底**：山河直接长在书页上，镜头连续下降进入，中间不切镜头、不换场景。

## 6. 体验流程

### 6.1 总流程

```text
黑屏 · 中央一枚朱砂印："点击入卷（建议佩戴耳机）"     ← 纯 HTML/CSS，兼作加载页
↓ 点击：解锁音频
烛火亮起 → 木桌显现 → 镜头缓慢推向书案
↓
古书自动打开，书页上竖排显现"诗境 · 一卷山河"
↓
[入卷] 推荐路线：直接进入《枫桥夜泊》
[选诗] 翻到目录，选择一首
[关于] 作品说明与署名
↓
书写：首句逐笔书写，其余诗句以墨洇的方式显现
↓
墨迹扩散，汇成山水轮廓
↓
纸面隆起，江河、树木、建筑、舟船依次墨显
↓
镜头下降，书页边缘退出画面 → 入境
↓
四句诗依次演出 → 自由观察 / 点击某句诗重演该句
↓
下一首：约 3 秒墨染切换（可跳过）；或"回卷"返回书案
```

对应的状态机：`gate → study → select → write → grow → explore`（见第 23 章）。

### 6.2 入口页：朱砂印

浏览器不允许未经用户操作就播放声音，所以"黑屏 → 轻微环境音"做不到。改为：

- 黑屏中央一枚朱砂印，写"点击入卷（建议佩戴耳机）"。
- 这一屏只有 HTML/CSS，在 three.js 和资源加载完成前就能显示，兼作加载页。印泥颜色随加载进度由浅到深，加载完成前印章不可点。
- 点击后：`AudioContext.resume()` 解锁音频 → 第一声是火柴 / 烛芯声 → 烛火亮起。

### 6.3 三个按钮

原设计中"入卷"和"选诗"功能重复，调整为：

| 按钮 | 行为 |
|---|---|
| 入卷 | 推荐路线，直接在当前书页上书写《枫桥夜泊》 |
| 选诗 | 翻到目录页，选择一首后在该页书写 |
| 关于 | 作品说明、制作方法、署名（CREDITS） |

### 6.4 竖排与阅读方向

线装书竖排，从右往左读，书页从左往右翻：

- DOM 中的诗句一律 `writing-mode: vertical-rl`。
- "诗句逐行出现"改为**从右到左逐列出现**。
- 书页（Canvas 贴图）上的排版同样竖排、右起。

### 6.5 时长预算

每首诗完整走一遍"书→墨→纸→山水"约一分钟，答辩通常只有几分钟，所以必须算账：

| 段落 | 时长 | 说明 |
|---|---|---|
| 书写 | ≈ 10 s | 只有首句（7 字）逐笔书写，其余三句以墨洇方式显现；28 字全部逐笔会超过一分钟 |
| 墨扩散 | ≈ 6 s | 与书写尾段重叠 |
| 隆起 + 场景生长 | ≈ 8 s | |
| 镜头入境 | ≈ 6 s | |
| 四句演出 | 4 × 8–10 s | |
| **合计** | **≈ 60–70 s** | |

- 首次入境走完整转场；诗与诗之间用约 3 秒的墨染切换（InkWipe，见 13.10），且**必须能跳过**。
- 所有段落都挂在全局时钟上，可以按数字键直接跳到某一幕（见 16.5）。

### 6.6 舒适性

- 白帝城高速穿越要防晕：不做镜头滚转，限制视角变化速度，保持地平线稳定（见 15.4）。
- 遵从系统的"减少动态效果"设置（`prefers-reduced-motion`）：高速段降速，大幅镜头运动改为淡入淡出切镜。

## 7. 首版诗词与三场景总览

V1 只做三首。三首诗在视觉风格、色彩、情绪和动态表现上必须有明显差异，且差异要能**对应到中国画史**，而不只是"颜色不同"：

| | 《枫桥夜泊》 | 《江雪》 | 《早发白帝城》 |
|---|---|---|---|
| 情绪 | 安静、清冷、孤寂、含蓄 | 空、静、寒、孤 | 轻快、壮阔、自由 |
| 画风 | 夜景设色：冷蓝 + 渔火暖光 | 水墨，大面积留白 | 青绿山水 |
| 画史参照 | 江南山水（董源一路） | 马远《寒江独钓图》 | 王希孟《千里江山图》 |
| 主色 | 深蓝、青灰、墨黑 + 暖橙 | 白、灰、墨 | 石青、石绿 + 朝霞 |
| 三远（郭熙） | 平远 | 平远 | 高远（绝壁）、深远（峡谷） |
| 山石笔触 | 披麻皴（江南土山） | 几乎不皴，以留白代雪 | 斧劈皴（峡江绝壁） |
| 声音主角 | 钟声 | 寂静 | 猿声 |
| 动态强度 | 中 | 极低 | 高 |
| 制作成本 | 中（主场景，最先做） | 低（复用最多） | 高（峡谷 + 高速 + 云海） |

制作顺序：枫桥 → 江雪 → 白帝城。

## 8. 场景一：《枫桥夜泊》

作者：张继　朝代：唐

> 月落乌啼霜满天，\
> 江枫渔火对愁眠。\
> 姑苏城外寒山寺，\
> 夜半钟声到客船。

### 8.1 场景定位

《枫桥夜泊》是整个项目的主场景，也是答辩主线和 P1 最小完整版唯一的场景。

视觉关键词：江南、夜色、落月、江面、渔火、枫树、枫桥、寒山寺、客船、钟声、薄雾。

整体情绪：**安静、清冷、孤寂、含蓄。**

### 8.2 场景组成

| 元素 | 来源 | 备注 |
|---|---|---|
| 地形、河岸 | 高度图（PaperTerrain） | 由书页隆起而成 |
| 江面 | 代码系统 water | 含钟声波纹 |
| 枫桥（石拱桥） | GLB | 可用 `build_bridge.py` 程序化生成 |
| 寒山寺、钟楼 | GLB | 唐风：出檐深远、屋坡平缓、鸱尾；可用 `build_temple.py` |
| 客船 | GLB | 镜头主位，"到"字的落点 |
| 渔船、渔火、灯笼 | GLB + behaviors | 灯笼 sway、渔火 flicker |
| 枫树 | GLB 单株 + 实例化 | Blender Geometry Nodes 摆放 |
| 芦苇、木桩、石岸 | GLB 单株 + 实例化 | 芦苇用顶点色 R 做风摆 |
| 上弦月（半月） | 代码系统 atmosphere | 见 8.4 |
| 夜空、云层、薄雾 | 代码系统 atmosphere | |
| 远山、姑苏城墙远影 | 剪影层 | 书页外的"画外之景"，见 13.7 |
| 乌鸦 | 代码系统 particles（Birds） | 少量 |
| 霜 | 代码系统 particles（Snow 复用，参数不同） | 月光下细微闪烁的霜晶 |

### 8.3 色彩与光照

主色：深蓝、青灰、墨黑。辅助色：冷白、青绿。强调色：暖黄、暖橙。

```text
冷色环境
+
暖色渔火
```

光照随诗句变化：第一句开始时月光是主光；月落之后天色转暗，**主光让给渔火**，冷暖对比由此加强。场景 LUT 偏冷蓝，渔火和灯笼走 Bloom。

### 8.4 天文："月落"不是明月高悬

"月落"发生在"夜半"之前，说明这是一轮在子夜前后西沉的月亮。月相与出没时间的关系是：

- 上弦月（农历初七、初八前后）约正午升起、子夜前后落下；
- 月亮每天大约晚升起 50 分钟。

所以场景应该是**半月沉入西山、亮面朝西（朝向已经落下的太阳）、天色随之转暗**，而不是一轮满月挂在天上。这是一个很好的"数学 + 文化"讲点，也写进文化面板。

### 8.5 逐句演出

| 诗句 | 机位（三远） | 画面 | 声音 |
|---|---|---|---|
| 月落乌啼霜满天 | 平远，远眺西山 | 半月沉入西山，天色转暗；乌鸦惊起、掠过；月光下霜晶闪烁 | 乌啼、风 |
| 江枫渔火对愁眠 | 平远，沿江岸横移 | 江岸枫树；渔火逐盏点亮，水面出现倒影；客船上人影静卧 | 水声、木舟轻响、虫鸣 |
| 姑苏城外寒山寺 | 平远，穿过薄雾 | 远处城墙轮廓掠过，雾中显出寒山寺与钟楼 | 风渐弱 |
| 夜半钟声到客船 | 客船上，面向寺庙 | 钟声波纹由寺前推向客船（见 8.6） | 钟声（波前到达时才响） |

### 8.6 核心动态：把"到"字演出来

原设计是"先响钟，再起波纹"。这没有体现"到"字：钟声是**传到**客船的。改为：

1. 撞钟瞬间，钟楼出现一闪微光（此时没有声音）。
2. 江面从寺前生出一圈波纹，波前以声速向外推进。
3. 镜头在客船上，迎着波纹看它从远处推来，雾被波前轻轻推开。
4. **波前抵达船身的那一刻，钟声响起**，客船随之轻晃。
5. 余韵：钟声回荡，波纹渐平，页面上诗句的"到"字墨色加深。

延迟 = 距离 ÷ 声速。寺到客船按设计尺度约 950 m 计，延迟 ≈ 950 ÷ 340 ≈ 2.8 s（分镜中的 `at: 2.8` 即来自这里）。这和"先见闪电、后闻雷声"是同一个道理，答辩时是一个直观的物理讲点。

波纹用公式计算而不是物理模拟：半径 `r = c·(t − t₀)`，振幅随距离和时间衰减。它是时间的纯函数，任何时刻都能直接跳转和复现（见 16.4）。

### 8.7 持续动态

全部写成时间的函数 f(t)，由全局时钟驱动：

- 水面波动与河面反射
- 薄雾缓慢移动
- 枫叶轻微摆动、少量枫叶飘落
- 小舟轻微摇晃（behavior: bob）
- 灯笼轻微摆动（behavior: sway）
- 渔火闪烁（behavior: flicker）
- 云层移动
- 远处乌鸦偶尔掠过

## 9. 场景二：《江雪》

作者：柳宗元　朝代：唐

> 千山鸟飞绝，\
> 万径人踪灭。\
> 孤舟蓑笠翁，\
> 独钓寒江雪。

### 9.1 场景定位

《江雪》的重点不是"复杂"，而是**留白**。它是整个项目中最极简、最省的场景，复用最多。

构图参考马远《寒江独钓图》：画面大面积空白，一叶孤舟、一个垂钓的人，江水只以寥寥几笔暗示，空白本身就是江、雪和寒意。

关键词：雪、山、江、孤舟、蓑笠翁、大面积留白、薄雾。

整体情绪：**空、静、寒、孤。**

### 9.2 场景组成

| 元素 | 来源 | 备注 |
|---|---|---|
| 层叠雪山 | 高度图 + 远山剪影层 | 越远越淡，最终融进纸白 |
| 江面 | 代码系统 water（复用） | 几乎静止 |
| 冰雪岸边、少量枯木 | GLB | |
| 孤舟 | GLB | 可复用枫桥的舟，换材质 |
| 蓑笠翁、钓竿、钓线 | GLB | 蓑衣用顶点色 R 做风摆 |
| 雪 | particles（Snow） | |
| 雾 | atmosphere（Fog） | 雾色 = 纸色，见 14.4 |

### 9.3 色彩

主色：白、灰、墨，尽量不用其他颜色。画面整体接近**中国水墨山水画**。

雪不是"画出来的白"，而是纸本身的颜色：雾和远景渐隐到纸白，留白就是雪。

### 9.4 逐句演出

| 诗句 | 机位（三远） | 画面 | 声音 |
|---|---|---|---|
| 千山鸟飞绝 | 平远，拉远 | 远处飞鸟逐渐消失，天空趋于安静 | 风声，最后一声鸟鸣后归于静 |
| 万径人踪灭 | 平远，缓慢横移 | 山路被雪覆盖，足迹消失，雾气增强 | 风雪 |
| 孤舟蓑笠翁 | 穿过雾层 | 江面出现孤舟，蓑笠翁逐渐墨显 | 风雪减弱 |
| 独钓寒江雪 | 停留，孤舟居画面中央偏下 | 雪势增强，其余一切淡去 | 只剩极轻的风雪与钓线声 |

### 9.5 动态

大雪、雾气流动、水面微弱波动、小舟轻摇、衣摆微动、钓线轻微运动。

动态必须非常克制。

### 9.6 声音

"静"需要被设计出来：环境音逐句减弱，最后一句几乎无声。

| 白帝城 | GLB | 唐风建筑群，立于绝壁之上 |

### 10.3 色彩：青绿山水

白帝城正好缺一节色彩设计，参考《千里江山图》：

- 山体：赭石打底，山体上部罩染石青、石绿，这是青绿山水的基本做法。

| 诗句 | 机位（三远） | 画面 | 声音 |
|---|---|---|---|
| 朝辞白帝彩云间 | 高远，仰视绝壁 | 朝霞彩云缭绕白帝城，轻舟离岸 | 晨风、江流 |

- 不做镜头滚转，地平线保持水平；
- 限制偏航和俯仰的角速度；
- 视角（FOV）基本恒定；
- `prefers-reduced-motion` 时降速，并用淡入淡出切镜代替高速穿越。

### 10.6 声音

江流、风声、**猿啼**（原音效表遗漏，这正是诗句本身）、峡谷回声、少量鸟鸣。

## 13. 核心转场：书页 → 山河

这是整个项目最核心、风险最大的系统，必须在 P0 先做技术验证（见第 28 章）。

原方案"Scale Y + 顶点位移"做出来，山会像被拉长的模型，因此改为下面的方案。

### 13.1 总体思路：三个统一

| 统一 | 含义 |
|---|---|
| 一张网格 | 书页和地形是同一张细分平面，高度来自高度图。开始时是平的纸，结束时是山河 |
| 一张遮罩 | 墨扩散的结果 `inkMask` 同时控制：高度、纸色 → 墨色 → 场景色、水面出现、物体墨显 |
| 一镜到底 | 山河直接长在书页上（整个世界缩到书页大小），镜头从书上方连续下降进入 |

模块分工：算法放在 `systems/`（ink、terrain、water…），`transition/PaperToWorld.ts` 只负责编排时序。

### 13.2 逐笔书写（BrushWriter）

- 笔顺数据：hanzi-writer / Make Me a Hanzi，覆盖 9000 多个常用字，每个字包含笔画轮廓和中线点列。项目只用到约一百个字，由工具抽取子集。
- 绘制：以笔画轮廓作裁剪，沿中线推进笔刷，压力随进度变化（起笔顿、行笔提、收笔回锋），笔锋有粗细，字形保持准确。
- 排版：竖排，右起。
- 书写过程画在一张 Canvas 上，这张 Canvas **直接作为墨扩散的墨源**。
- 只有首句逐笔书写，其余诗句直接以墨源形式注入、靠扩散"洇"出来（见 6.5）。

### 13.3 墨扩散（InkSim）

- 实现：两个渲染目标交替迭代（ping-pong），每步读上一张、写下一张。
- 状态通道：R = 水分，G = 流动的墨，B = 已沉积的墨，A = 预留。
- 每一步：水分向邻居扩散，墨随水走，水分下降时墨沉积；湿边处墨更浓，形成"积墨"的深色边缘。
- 扩散速度 = 基础速度 × **宣纸纤维噪声** × **引导遮罩**：
  - 纤维噪声（各向异性的长纤维纹理）让边缘出现不规则的"洇"的毛边；
  - 引导遮罩由 Blender 烘焙（`bake_terrain.py`），让墨优先流向山的轮廓，而江河所在处保持留白——**江就是纸上的留白**，这本身就是中国画的做法。这样"墨迹汇成山水轮廓"是可控的，而不是随机的。
- 分辨率：高档 1024²，低档 512²。需要半精度浮点渲染目标，不支持时降级。
- 可复现：固定步长、固定种子。跳转时从 0 重新快进（几百步在 GPU 上只要几帧），或在关键时间点缓存快照。
- 理论参考：MoXi（Chu & Tai，*MoXi: Real-Time Ink Dispersion in Absorbent Paper*，SIGGRAPH 2005），专门研究宣纸吸墨。本项目用简化的扩散模型，借鉴其"纤维决定渗透率"和"湿边积墨"两点。答辩时可以作为技术亮点讲。

### 13.4 纸面隆起（PaperTerrain）

- 网格：细分平面，高档 512×512，低档 256×256。
- 高度图：由 `bake_terrain.py` 从 Blender 地形烘焙。浏览器解码 PNG 只有 8 位，所以把 16 位高度拆进 R（高 8 位）、G（低 8 位）两个通道，B 通道存 13.3 的引导遮罩；加载时在 JS 里一次性解码成浮点纹理，之后可以正常线性采样。
- 顶点着色器：

  ```text
  高度 = height(uv) × uGrow × smoothstep(a, b, inkMask(uv)) × edgeFade(uv)
  ```

  `edgeFade` 让书页边缘始终保持平整，入境过程中书页边缘清晰可见。
- 法线：由（高度 × 遮罩）的有限差分在着色器中重新计算，遮罩每帧变化，法线跟着变化。
- 颜色三段：纸色 → 墨色（由 `inkMask` 控制）→ 场景色（由 `uColorize` 控制，按高度和噪声错开，颜色也像"染"上去的）。
- 水面：在高度低于水位处，随 `uGrow` 淡入。

### 13.5 文字意象化

不必所有字都转化。每首诗挑 2–3 个字（如枫桥的"月""舟""钟"）：

- 从字形（BrushWriter 画出的字）采样出点云；
- 用 three.js 自带的 `MeshSurfaceSampler` 在目标模型表面采样同样数量的点；
- 两组点按主轴排序配对，粒子沿带噪声的曲线飞向目标点，位置是时间的函数；
- 粒子到达后淡出，目标模型同时墨显。

### 13.6 场景生长（墨显）

- 物体不是"凭空出现"，而是墨显：噪声阈值溶解，溶解边缘先是墨黑，再过渡到材质本色（`chunks/inkReveal.glsl`）。
- 生长顺序：山 → 江 → 树 → 建筑 → 舟 → 人物 → 粒子 → 环境光，不要同时出现。
- 每个物体的出现时刻来自 GLB 自定义属性 `reveal`（0–1，对应生长阶段内的相对时间，见第 18 章），不必在代码里逐个写。

### 13.7 镜头进入与尺度

- 书页物理尺寸约 0.3 m，世界按米制作。入境前世界根节点缩放 `s = 书页尺寸 / 世界尺寸`（例如 0.3 m / 1500 m = 2×10⁻⁴），山河真的长在书页上。
- 镜头从书上方沿曲线下降到 Blender 中定义的 `CAM_enter` 机位。
- 下降过程中按离地高度动态调整：`near = k × 离地高度`，`far = near × R`（R 固定）。透视深度缓冲的精度只取决于 near/far 的比值，和绝对尺寸无关，所以全程不需要切镜头、不需要换场景，也不会出现深度冲突。
- 书页外围：天空穹顶和远山剪影层在入境后半段淡入，雾把书页边界和书房吞没——**画外之景由雾生成**，这也是留白。
- 归一化：书页边缘退出画面、书房被雾完全遮住后，在同一帧内隐藏书房、把世界缩放恢复为 1，镜头位置和 near/far 同比换算，画面没有任何跳变。此后所有场景逻辑都在米制下运行，和第 18 章的契约一致。阴影相机、雾距离等参数一律写成"世界单位 × 当前缩放"。

### 13.8 时序（以枫桥为例）

| 时间 | 事件 |
|---|---|
| 0–10 s | BrushWriter 书写首句；其余三句注入墨源 |
| 4–16 s | InkSim 墨扩散，汇成山水轮廓 |
| 12–20 s | `uGrow` 0 → 1，纸面隆起，水面淡入 |
| 16–24 s | 物体按 `reveal` 依次墨显；2–3 个字化为点云飞向对应物体 |
| 18–26 s | 镜头下降，远景和雾淡入 |
| ≈ 26 s | 尺度归一化，隐藏书房 |
| 26 s 起 | 第一句演出 |

全部挂在全局时钟上，可以跳转（见 16.4）。精确时间码写进 `STORYBOARD.md`。

### 13.9 降级方案

如果 P0 验证后"隆起"效果不可信：**纸被墨浸透后溶解，露出其后已经搭好的三维场景**，镜头穿过纸面进入。"一页纸，生出一片山河"的记忆点仍然成立，工作量显著减少。

### 13.10 诗与诗之间：InkWipe

- 约 3 秒：一滴墨从画面中心洇开，盖住当前场景 → 切换 → 墨从边缘褪去，露出新场景。
- 这是"墨"的转场，不属于"直接切场景"。
- 可跳过（点击或 Esc）。
- 切换前由 SceneManager 预加载下一首。

## 14. 水墨渲染方案

原技术栈里没有真正决定画面气质的部分，本章补上。

### 14.1 渲染器约定

- **写死 WebGLRenderer + GLSL**。GLSL 写的 ShaderMaterial 只有 WebGLRenderer 支持，WebGPURenderer 要用 TSL 全部重写。定了 GLSL 就不要中途换渲染器。
- three.js 锁定精确版本，项目周期内不升级。
- 后处理用 three.js 自带的 EffectComposer + ShaderPass。

### 14.2 水墨材质（InkMaterial）

- 用 `onBeforeCompile` 改造 MeshStandardMaterial，保留光照和阴影，在其上注入：
  - 色阶：把光照量化成几档墨色（焦、浓、重、淡、清）；
  - 积墨：凹处和顶点色 G 通道（AO）处墨更重；
  - 墨显：13.6 的溶解。
- GLB 里的材质按材质名替换成对应的 InkMaterial 变体（见 18.4）。

### 14.3 后处理（PostFX）

| 顺序 | 效果 | 作用 |
|---|---|---|
| 1 | 深度 + 法线描边 | 模拟笔线，线宽受噪声调制，远处变细变淡 |
| 2 | Kuwahara 滤镜 | 把色块抹成笔触，做出晕染感 |
| 3 | Bloom（仅高亮） | 渔火、烛火、朝霞 |
| 4 | LUT 调色 | 每个场景一张（白帝城三张按天色插值） |
| 5 | 宣纸纹理叠加 | 让整个画面像画在纸上 |

法线用多渲染目标（MRT）输出，或单独以低分辨率渲染一遍。

### 14.4 雾与留白

深度雾渐隐到**纸白**而不是灰：远山淡去，就是留白。江雪场景尤其依赖这一点。

### 14.5 山石：皴法 + triplanar

山石不用照片贴图（和水墨冲突），改用手绘 / 程序生成的皴法笔触纹理，以 triplanar 方式投射，省去 UV 展开：

- 枫桥：披麻皴（江南土山的长线条）；
- 白帝城：斧劈皴（峡江绝壁的块面）；
- 江雪：几乎不皴，以留白代雪。

### 14.6 三场景画风

见第 7 章总览表：江雪 = 水墨（马远），枫桥 = 夜景（冷蓝 + 渔火），白帝城 = 青绿（《千里江山图》）。

### 14.7 性能提醒

这类画面的主要开销在半透明雾层的叠加和全屏后处理，而不在面数。详见第 24 章。

## 15. 镜头系统

### 15.1 四种模式

由 `systems/camera/CameraDirector.ts` 统一管理：

| 模式 | 说明 |
|---|---|
| Orbit | 用户自由环视。限制俯仰角和距离，不钻地、不穿模 |
| Cinematic | 分镜驱动的电影镜头，机位来自 Blender 的 `CAM_` 相机 |
| Focus | 点击诗句后，镜头飞向该句对应的 `FOCUS_` 焦点 |
| Guided Tour | 自动游览。用户一拖动就暂停，若干秒无操作后恢复 |

### 15.2 机位来源

- 每句诗的机位直接在 Blender 里用相机构图，命名 `CAM_<名称>`，导出后代码只取位置、朝向和垂直视角。
- 焦点用空物体 `FOCUS_<名称>` 标记。
- 代码里不写死任何坐标。

### 15.3 三远

镜头类型引用郭熙《林泉高致》的"三远"，直接体现在机位属性和命名上（`yuan: "gao" | "shen" | "ping"`）：

| 三远 | 原意 | 用在 |
|---|---|---|
| 高远 | 自山下而仰山巅 | 白帝城绝壁 |
| 深远 | 自山前而窥山后 | 白帝城峡谷 |
| 平远 | 自近山而望远山 | 江雪、枫桥 |

### 15.4 防晕规则

- 不做镜头滚转；
- 限制角速度；
- FOV 基本恒定；
- 遵从 `prefers-reduced-motion`（见 6.6）。

### 16.4 全局时钟与 f(t)

- `engine/Engine.ts` 持有唯一的全局时钟，可以暂停、可以跳转。
- 所有动画都写成时间的纯函数 f(t)；随机数一律用带固定种子的生成器（`utils/random.ts`），不用 `Math.random()`。
- GSAP timeline 设为暂停状态，由全局时钟每帧 `seek(t)`，与 f(t) 同源。
- Blender 导出的骨骼 / 形变动画同样由时钟驱动（`mixer.setTime(t)`）。
- 不能写成纯函数的仿真（InkSim）按固定步长推进，跳转时快进（见 13.3）。

这样就能：用 `?scene=fengqiao&t=42` 直接跳到指定时刻；在固定时刻截图对比；答辩时按数字键直接跳到某一幕；逐帧录制视频。

### 16.5 调试入口

| 入口 | 作用 |
|---|---|
| `?scene=<id>&t=<秒>` | 跳到某场景某时刻 |
| `?q=high\|mid\|low` | 强制画质档位 |
| `?debug` | 显示 lil-gui 参数面板 |
| 数字键 1 / 2 / 3 | 跳到三首诗 |
| ← / → | 上一句 / 下一句 |
| 空格 | 暂停 / 继续 |
| `window.__POETIC__` | 暴露 `seek(t)`、`step(dt)`、当前状态，供 tools 使用 |

## 17. 音频设计

音效对本项目非常重要：声音是"被听见"的那一半。

### 17.1 解锁与总线

- 入口页点击时解锁 AudioContext（见 6.2）。
- 四条总线：环境（ambience）、音效（sfx）、人声（voice，朗读）、音乐（music，古琴）。人声出现时其他总线自动压低。

### 17.2 循环与空间声

- 环境音循环用 Web Audio 的 AudioBuffer（`AudioBufferSourceNode.loop`），不用 `<audio loop>`，后者会有接缝。MP3 头尾带编码填充，循环素材要设置 `loopStart / loopEnd` 裁掉，或改用 m4a。
- 声源位置来自 GLB 的 `SFX_` 空物体，用 PannerNode 做空间化（钟声、渔舟、猿啼）。
- 峡谷回声用卷积混响（ConvolverNode）。

### 17.3 与时钟同步

- 一次性音效由分镜 cue 触发。
- 跳转时环境音从对应偏移处重新开始；全局时钟暂停时挂起 AudioContext。
- 录制视频时音频单独按时间码混出，再与画面合成。

### 17.4 音效清单

| 范围 | 声音 |
|---|---|
| 公共 | 书页翻动、毛笔落纸与书写、墨滴、烛芯、风、竹叶、木屋细微声响、古琴 |
| 枫桥 | 水声、风声、**乌啼**、古钟、木舟、远处虫鸣 |
| 江雪 | 风雪、极轻水声、远处风声、钓线；强调"静" |
| 白帝城 | 江流、风声、**猿啼**（左右交替）、峡谷回声、少量鸟鸣 |
| 人声 | 每句诗一段朗读 / 吟诵 |

### 17.5 "被听见"

v1 第 3.3 节提到古琴、第 32 节说"被听见"，但都没有落实：

- **朗读 / 吟诵**：每句诗演出时配一段朗读。同学自己录最省事，也最原创。
- **古琴**：书房和选诗阶段的底乐。注意：古曲本身是公版，不代表某个录音是公版。要么自录，要么用许可明确的录音，并记入 CREDITS。

## 18. Blender ↔ 代码契约

> 定稿后迁移到 `docs/CONTRACT.md`，以其为唯一来源。这是 Blender 和代码之间唯一的约定：没有它，在 Blender 里改一个物体名，代码就会悄悄失效。

### 18.1 坐标与原点

- 单位：米。
- Blender 的 Z 轴向上，导出后变成 Y 轴向上。
- 模型正面在 Blender 里朝 −Y，到 three.js 里就朝 +Z。
- 落地物体的原点放在底面中心。
- 导出前应用所有变换（旋转、缩放归一）。
- 物体名、材质名只用 ASCII，小写加下划线。

### 18.2 命名前缀

| 前缀 | 含义 | 例 |
|---|---|---|
| `CAM_` | 每句诗的机位（Blender 相机） | `CAM_boat`、`CAM_enter` |
| `FOCUS_` | 镜头焦点（空物体） | `FOCUS_bell` |
| `EMIT_` | 波纹、粒子的发射点 | `EMIT_bell` |
| `SFX_` | 声源位置 | `SFX_bell`、`SFX_ape_left` |
| `LIGHT_` | 灯光位置标记，灯光本身由代码创建 | `LIGHT_fishfire_01` |

### 18.3 自定义属性 → userData

导出时勾选 Custom Properties，three.js 里就能从 `userData` 读到。前端按属性自动挂行为，不必每个物体写一个 JS 文件：

| 属性 | 取值 | 作用 |
|---|---|---|
| `behavior` | `"bob"` \| `"sway"` \| `"flicker"` | 由 `systems/behaviors` 自动挂载 |
| `reveal` | 0–1 | 生长阶段内的出现时刻（见 13.6） |
| `yuan` | `"gao"` \| `"shen"` \| `"ping"` | 仅 `CAM_`，三远类型（见 15.3） |

### 18.4 材质名当槽位

Blender 里的程序化节点本来就导不出去，所以材质只作为"槽位"，前端按材质名替换成对应的 shader 材质：

| 材质名 | 前端替换为 |
|---|---|
| `ink_rock` | 山石：皴法 triplanar + 色阶 |
| `ink_wood` | 木构：建筑、船 |
| `ink_foliage` | 枝叶：枫树、芦苇、树林 |
| `ink_cloth` | 衣物：蓑衣 |
| `water` | 水面 |
| `paper` | 纸：书页 |
| `snow` | 积雪 |
| `glow` | 自发光：渔火、灯笼、烛火 |

### 18.5 顶点色当遮罩

| 通道 | 含义 |
|---|---|
| R | 风吹摆动权重（蓑衣、芦苇、灯笼） |
| G | AO / 积墨 |
| B、A | 预留 |

导出时顶点色选 Active。默认设置只导出被材质用到的顶点色，而这里的顶点色是给 shader 用的，不会被 Blender 材质引用。

### 18.6 植被与实例化

- Blender 里只做单株，用 Geometry Nodes 摆放。
- 导出摆放矩阵，前端生成 InstancedMesh。两条路 P0 时验证哪条更稳：由 `export_glb.py` 把实例变换写成 JSON；或使用 glTF 的 `EXT_mesh_gpu_instancing` 扩展（GLTFLoader 会直接还原成 InstancedMesh）。

### 18.7 预算

| 项 | 上限 |
|---|---|
| 每个场景（压缩后） | ≤ 15 MB |
| 单张贴图 | ≤ 2K |
| 每个场景 draw call | < 500 |
| 静态物体 | 导出前按材质合并 |

不要学参考仓库 sakura 的"一物一文件、不合并网格"：它自己实测就是被 draw call 拖到了 20 fps 左右（约 10 µs 一次 draw call，瓶颈不在像素）。

### 18.8 程序化建模

寺庙、桥、舟这类规则造型可以写成 `art/scripts/build_*.py`，用 Blender Python 程序化建模（参考仓库拖拉机的做法），`.blend` 可以随时从脚本复生成，参数改起来也快。

## 19. 资产制作与处理流程

### 19.1 流程

```text
art/blender/*.blend
  ← art/scripts/build_*.py（可选：程序化生成）
↓ art/scripts/validate.py        命名、原点、面数、材质名检查
↓ art/scripts/export_glb.py      统一导出参数，按集合导出
↓ tools/optimize-assets.mjs      gltf-transform：Meshopt 几何压缩、贴图缩放 / 转 WebP、去重、裁剪
↓ public/assets/models/<scene>/
↓ tools/check-contract.mjs       分镜引用的 CAM_ / FOCUS_ / EMIT_ / SFX_ 是否都在 GLB 里
↓ tools/check-budget.mjs         GLB / 贴图 / 音频体积预算
↓ 前端加载
```

地形另走一条：`art/scripts/bake_terrain.py` → `public/assets/terrain/<scene>.height.png`（RG = 16 位高度，B = 墨迹引导遮罩）。

Blender 脚本统一用 `blender -b <文件>.blend --python art/scripts/<脚本>.py` 无头运行。

### 19.2 压缩

- 先用 Meshopt + WebP 起步：Meshopt 解码器随 three.js 提供（JS 内嵌 wasm），不需要额外部署 wasm 文件，也不用装外部工具。
- 需要省显存（手机）时再上 KTX2，届时才需要 `public/decoders/basis/`。
- 教训：参考仓库 terra-728 的 GLB 没压缩，拖拉机有 29 MB。单模型展示能忍，本项目是多场景连续体验，忍不了。

### 19.3 源文件管理

`art/` 是制作端，浏览器永远看不到。`.blend`、贴图源文件、音频源文件用 Git LFS 管理。

## 21. 文化考据

评委最容易注意到的是文化细节。下列内容用于文化面板和答辩讲解，文案写进 `content/poems/*.json` 的 `background` / `trivia` 字段。

### 21.1 《枫桥夜泊》

- **月落**：上弦月约子夜西沉，与"夜半钟声"的时序吻合（见 8.4）。
- **钟声"到"客船**：延迟 = 距离 ÷ 声速（见 8.6）。
- **半夜钟**：欧阳修在《六一诗话》里质疑"句则佳矣，其如三更不是打钟时"；宋人叶梦得等后来考证，吴中寺院确有半夜打钟的习惯。
- **霜满天**：霜并不从天而降，"霜满天"写的是弥漫天地的寒气，这是诗人的感受而不是气象描述。

### 21.2 《江雪》

- 作于柳宗元贬居永州期间；"千山""万径"之大与"孤舟""独钓"之小形成对照。
- 马远《寒江独钓图》：几乎整幅空白，只画一舟一人，是"留白"最好的注脚。

### 21.3 《早发白帝城》

- 一般认为作于李白流放夜郎途中遇赦东归时。
- 郦道元《水经注·江水》："或王命急宣，有时朝发白帝，暮到江陵，其间千二百里，虽乘奔御风，不以疾也。"——"朝发暮到"正是 10.3 中天色从朝霞走到暮色的依据。
- 同篇还记三峡"常有高猿长啸"，渔者歌曰"巴东三峡巫峡长，猿鸣三声泪沾裳"——猿声是三峡最有代表性的声音。

### 21.4 建筑与画法

- **建筑统一用唐风**：三首都是唐诗。出檐深远、屋坡平缓、屋脊两端用鸱尾，参考佛光寺东大殿（唐大中十一年，857 年）。避开明清彩画，也符合"克制"。
- **三远**：郭熙《林泉高致》（见 15.3）。
- **皴法**：披麻皴（江南土山）、斧劈皴（峡江绝壁）（见 14.5）。

### 23.4 场景生命周期

每个场景继承 `SceneBase`，统一五个阶段：

| 阶段 | 职责 |
|---|---|
| `load()` | 加载 GLB、高度图、音频；按材质名替换材质；按 userData 挂行为 |
| `enter()` | 注册分镜，淡入环境音 |
| `update(t)` | 只依赖全局时间 t |
| `exit()` | 停止音频，释放交互 |
| `dispose()` | 释放几何、材质、贴图、渲染目标 |

SceneManager 负责加载、进入、退出、释放，并在当前场景演出时预加载下一首，避免不同诗词场景代码互相污染。

## 24. 性能与画质分档

### 24.1 开销排序

1. 半透明雾层的叠加（overdraw）和全屏后处理（尤其 Kuwahara）；
2. draw call（参考仓库实测约 10 µs 一次）；
3. 面数。

所以 LOD 的优先级放低，先控制雾层和后处理，再合并网格、实例化。

### 24.2 措施

- 雾层数量、分辨率随档位变化；
- 静态物体按材质合并；
- 植被、雪花、落叶用 InstancedMesh 或 Points + Shader；
- 场景退出时释放所有 GPU 资源。

### 24.3 画质分档

启动时按设备检测定一个初始档位；运行中若持续数秒低于阈值就降一档。**只降不升**，避免画质来回跳。

| 项 | 高 | 中 | 低 |
|---|---|---|---|
| pixelRatio | min(dpr, 2) | 1.5 | 1 |
| InkSim 分辨率 | 1024² | 512² | 512²（步数减半） |
| 地形细分 | 512² | 384² | 256² |
| Kuwahara | 全分辨率 | 半分辨率 | 关 |
| 描边 | 深度 + 法线 | 深度 + 法线 | 仅深度 |
| 雾层 | 全部 | 减半 | 最少 |
| 雪 / 落叶粒子 | 100% | 60% | 30% |
| 阴影 | 2048 | 1024 | 关（靠顶点色 AO） |
| Bloom | 开 | 开 | 关 |

## 28. 开发阶段

v1 说 PaperToWorld 最重要，却排在书房（Phase 2）、选诗（Phase 3）之后；Phase 2 还要求"首页本身能独立作为完整视觉作品"，这一步很容易把时间耗光。v2 按"核心优先"重排。具体日期在第 3 章截止日期确定后排定。

### P0 · 技术验证（1–2 周）

- 用灰模做：纸面 + 高度图 + 墨扩散 + 镜头下降 + 尺度归一化。

## 29. 砍需求顺序

时间不够时按以下顺序砍：

1. 移动端完整适配（保留"能打开、能看完"）；
2. 白帝城降级为一段穿峡长镜头（去掉云海和白帝城建筑细节）；

## 30. 禁止事项

### 30.1 体验

- **禁止过度 UI**：3D 场景始终是主角。
- **禁止所有场景使用同一风格**：三个诗境必须明显不同（见第 7 章）。
- **禁止直接切场景**：首次入境必须走完整的 书 → 墨 → 纸 → 山水；诗与诗之间用墨染切换（13.10）。
- **禁止大量无意义动态**：动画必须服务诗词。
- **禁止游戏化**：不要血条、任务、积分、游戏地图、HUD。
- **禁止大量现代 UI**：保持留白、简洁、古籍气质。
- **禁止明清彩画、宫廷元素**：建筑统一唐风。

### 30.2 工程

- 禁止在场景目录里用代码建模本该在 Blender 做的几何。
- 禁止动画依赖真实时间或 `Math.random()`：一律用全局时钟和带种子的随机数。
- 禁止中途更换渲染器（14.1）。
- 禁止在代码里写死机位坐标：机位来自 Blender `CAM_`。
- 禁止未登记来源的素材进入 `public/`（第 26 章）。

## 33. 项目核心设计总结

最终作品不应该让用户认为这是：

> 一个展示古诗的网页。

而应该让用户认为：

> 这是一个可以进入中国古典诗词世界的数字山水空间。

整个项目的设计核心可以浓缩成一句话：

> **以书卷为入口，以水墨为桥梁，以三维山河为载体，让中国古典诗词从文字变成可被看见、听见和进入的空间。**

其中"看见"靠一页纸生出山河，"听见"靠钟声、猿声与朗读，"进入"靠一镜到底。

最终体验应该完成：

```text
读诗
↓
见诗
↓
入诗
↓
游诗
```

的完整转变。
